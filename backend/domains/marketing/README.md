# agents/marketing
담당: 재헌 · 포트: 8103
## 1. 역할
마케팅 에이전트. 통합 에이전트가 넘긴 사건·상품 사실로 **공지**를 만들고 게시하며, 고객지원·재무가 공지 사실과 약속을 읽을 수 있게 하고(`get_notice`), 사건 보상·캠페인 **쿠폰**을 지급한다.
- v0은 시나리오 A 필수 skill 4개(`draft_notice`, `publish_notice`, `get_notice`, `issue_coupon`)다. 저장소는 메모리(목 모드)이고, 공지 문안은 LLM이 사실 필드만 보고 쓰고 코드 검증(`notice_text.py`)을 통과해야 쓴다. 실패하거나 LLM이 없으면 사실 필드만 쓰는 고정 템플릿이다(`source`, `text_check.reasons`).
- 캠페인(`draft_campaign`·`create_campaign`·`campaign_report`)은 권장·선택이라 이후에 만든다.
## 2. 실행 방법
- 서버: `docker compose -f infra/compose.yml up marketing`, 또는 `uv run uvicorn marketing_agent.main:app --port 8103`
- 목 모드: `MARKETING_MOCK=1` (LLM·외부 호출 대신 가짜 응답. CI는 항상 1)
- 단독 테스트: `uv run pytest agents/marketing`
- 요청 보내 보기: `uv run ax-test-call --agent http://localhost:8103 --skill get_notice --input input.json`

### 미디어 생성 (`generate_media`)
이미지(gpt-image-2)·영상(Gemini Omni) 생성의 **기반**이다. 이번 범위에는 실제 공급자 호출이 없고 목 어댑터(`marketing_agent/media/mock.py`)만 있다. 실제 공급자 이름을 설정하면 어댑터가 없다는 이유(`provider_adapter_missing`)로 호출 전에 거부한다.
- 프롬프트: 자유 입력 금지. `media/scene_templates.toml`의 고정 문장 + 화이트리스트 필드. 개인정보·고객 원문 말투·글자 요청·실존 인물·브랜드는 코드 검사로 `prompt_rejected`(`reason_code`와 필드 이름만 돌려주고 값은 되돌리지 않는다). 글자는 모델이 그리지 않고 오버레이가 넣는다.
- 영상 소리는 `MARKETING_AUDIO_MODE`가 정한다. 기본 `source`는 공급자가 만든 소리를 그대로 두고(`MediaRequest.remove_audio=False`) 별도 BGM은 만들지 않는다. 소리를 만들지 않는 공급자·모델(Runway·Vidu·Pixverse·Kling 일부 등)은 무음 영상이고, 클립을 이어 붙인 영상(`clip_count>1`)은 이음새·내용이 어긋나 소리를 버린다(`audio_note=clip_concat_muted`). `off`는 예전처럼 항상 무음, `bgm_overlay`는 영상 소리를 버리고 BGM을 한 번에 입히는 예전 묶음 흐름. 모르는 값(오타)은 `off`다. 결과에 `ai_generated: true`를 항상 남기고 `muted`·`has_audio`·`audio_mode`가 최종 파일의 소리 상태를 기록한다.
- 우리 키 사용량 예산 화면 설정(스킬 이름은 예전 그대로): `get_media_cost_limits`(읽기)·`lower_media_cost_limits`(재무·총괄이 하향 셀프 승인을 켠 경우만 확인 뒤 A, 아니면 C)·`raise_media_cost_limits`(C, 요청자≠승인자)·`set_cost_limit_option`(A, 정책 담당). 종류별 월 예산(영상 초 `video_seconds_monthly`·이미지 장 `image_count_monthly`·BGM 곡 `audio_count_monthly`)은 `MARKETING_COST_LIMITS_FILE`(기본 `<MARKETING_MEDIA_DIR>/cost_limits.json`, 이력 `.history.jsonl`)의 화면 값이 환경변수(`MARKETING_QUOTA_*`)보다 우선하며 mtime으로 재시작 없이 반영된다. 저장은 하한 1·코드 절대 상한 안에서만 된다. 예전 원화 칸(`video_per_item_krw`·`monthly_budget_krw`)을 보내면 `deprecated_krw_limit`로 거절한다.
- 영상 공급자 선택: `list_video_providers`(읽기)·`select_video_provider`(A)·`save_custom_video_provider`(C, 사람 승인)·`delete_custom_video_provider`(A). 어댑터는 `media/<이름>_video.py`에 `AsyncVideoProvider` 하위 클래스를 두면 자동 등록되어 목록·화면에 나온다(`registry.py`를 안 고쳐도 됨). 화면에서 고른 값은 환경변수 `MARKETING_VIDEO_PROVIDER/MODEL`보다 우선하고 `MARKETING_VIDEO_PROVIDERS_FILE`(기본 `<MARKETING_MEDIA_DIR>/video_providers.json`)에 저장되며 변경 이력은 `.history.jsonl`에 남는다.
- 커스텀 공급자(`custom:<id>`): 선언형 JSON 스펙(`media/custom_spec.py`)으로 목록에 없는 비동기 영상 API(제출 → 작업 ID → 상태 조회 → 결과 URL)를 붙인다. 호스트는 운영자 환경변수 `MARKETING_CUSTOM_VIDEO_ALLOWED_HOSTS`(쉼표 목록, 비면 사용 불가)에 있는 https 443만, 키는 `MARKETING_CUSTOM_*` 환경변수 이름만(값은 저장·응답·로그에 없음), 가격(`pricing.perSecondUsd`)·길이·해상도 상한 필수, 새 공급자는 `enabled=false`로 저장한다. 모든 요청은 `safe_fetch`의 공용 주소 전송만 지나고 응답 1MB·시간당 제출 20건·작업당 폴링 상한을 지킨다. 이미지 선업로드가 필요한 공급자는 범위 밖이다.
- 사용량(원화 없음): 단위는 공급자 단위 그대로 영상 `seconds`(클립 길이 합)·이미지 `images`·BGM `tracks`(`media/usage.py`)이고, 응답에 토큰이 있으면(Gemini) 입력·출력 토큰을 같이 남긴다. 우리 키(`MARKETING_MEDIA_KEY_OWNER=server`, 기본)로 실제 공급자를 부를 때만 종류별 월 예산을 걸고(`MARKETING_QUOTA_*`, 비었으면 `quota_not_configured`로 거부), (월 확정+예약+추정) 사용량이 예산을 넘으면 공급자를 부르지 않는다(`quota_exceeded`, 남은 %). 고객사 키(`customer`)는 예산을 안 건다. `media/prices.toml`은 호출 조건이 아니라 모델 능력표(클립 최대 길이)·공급자 목록용으로만 읽고, 표에 없어도 막지 않는다. `GeneratedMedia.cost_krw`·`cost_est_krw`는 예전 필드라 늘 0이다.
- 장부: SQLite `MARKETING_MEDIA_LEDGER_DB`(run_all.sh는 `.data/marketing_media_ledger.db`, 비우면 메모리라 월 사용량이 0으로 돌아간다). 키별 예약 → 확정(`usage_unit`·`usage_actual`·`input_tokens`·`output_tokens`·`usage_source` actual|estimate). 토큰이 없으면 단위 사용량(예상=요청한 만큼)을 남긴다. 옛 원화 장부 파일은 열 때 사용량 칸을 더하고 옛 행은 사용량 0으로 센다. 열 수 없으면 시작 때 실패한다.
- 관문: `execute("generate_media", {media_kind, usage_unit, usage_amount, ...})`(원화 금액 없음, safety 규칙은 매체 종류·영상 길이만)가 `executed`일 때만 공급자를 부른다. 멱등 키 `<context_id>:generate_media:<post_draft_id>:<요청 해시 앞 10자>`, 같은 키 재요청은 이전 결과(`replayed: true`)를 돌려준다. safety 등록부에 아직 없어 live 관문에서는 fail-closed다.
- 환경변수: `MARKETING_IMAGE_PROVIDER/MODEL`, `MARKETING_VIDEO_PROVIDER/MODEL`(공급자 기본 `mock`, 모델 기본 비움), `MARKETING_IMAGE_API_KEY`·`MARKETING_VIDEO_API_KEY`(이름만 정의), `MARKETING_QUOTA_VIDEO_SECONDS_MONTHLY`·`MARKETING_QUOTA_IMAGE_COUNT_MONTHLY`·`MARKETING_QUOTA_AUDIO_COUNT_MONTHLY`, `MARKETING_MEDIA_KEY_OWNER`, `MARKETING_MEDIA_LEDGER_DB`, `MARKETING_MEDIA_DIR`. 기본값은 없다(`.env.example`).
### `publish_sns` 게시 흐름 (설계 문서 6절, 분석 A-3)
- 상태 기계(게시 대기 저장소, SQLite): `held → approved → publishing → published | failed`, 거절·만료는 `held → rejected`. 전이는 compare-and-swap 한 번이라 이벤트가 두 번 와도, 이벤트와 폴링이 겹쳐도 `publishing`에 들어가는 쪽은 하나뿐이다. `publishing` 이상은 재진입하지 않는다.
- 승인 알림은 `safety.review_decided` 구독(action=`publish_sns`, 요청자=`marketing`만)이 1차다. `REDIS_URL`이 없으면 구독자는 꺼지고(로그 `sns_subscriber_disabled`, `runtime_status()`), `MARKETING_SNS_REVIEW_POLL_S`마다 대기 건의 `GET /api/safety/reviews/{review_id}`를 확인하는 폴링이 이어 준다. 마케팅이 스스로 승인하는 경로는 없다(결정 API는 사람 토큰만).
- 승인을 받으면 내용 해시를 다시 계산해 키와 같은지 보고(다르면 `content_changed`, 새 승인 필요), 같으면 **같은 키로** `execute()`를 다시 불러 `executed`(멱등 재생)를 받은 뒤에만 어댑터를 부른다.
- 어댑터 흐름: 컨테이너 생성(`is_ai_generated=true`, `share_to_feed` 항상 명시) → 상태 조회(`IN_PROGRESS`→`FINISHED`) → `media_publish`(성공 1회) → 미디어 조회(`permalink`·`timestamp`·`media_product_type`·`is_ai_generated` 응답값 기록). 응답을 잃으면 다시 게시하지 않고 컨테이너 `status_code`가 `PUBLISHED`인지로 판정하고, 확인하지 못하면 `publish_unconfirmed`로 닫는다.
- 실패 분류(분석 A-1 표): 일시 오류(`24/2207008`, `-2/2207003`, `-1/2207001·2207032·2207053`, `9007/2207027`)만 백오프(상한 `MARKETING_SNS_MAX_RETRIES`), `24/2207006`·`-2/2207020`은 새 컨테이너 1회, 한도(`9/2207042`)·스팸(`4/2207051`)·계정 제한(`25/2207050`)·URL(`9004/2207052`)·형식(`352/2207026`)·토큰(`190`)·모르는 코드는 즉시 `failed`. 재시도는 같은 `execution_id` 아래에서만 하고, `failed`가 된 키는 다시 열리지 않는다(내용을 바꾸면 새 키·새 승인).
- 환경변수(값은 모두 선택): `MARKETING_SNS_PROVIDER`(`mock` 기본, `instagram`), `MARKETING_IG_MEDIA_BASE_URL`(로컬 자산을 Meta가 받을 공개 HTTPS 주소, `media_ref`가 `https://`면 불필요), `MARKETING_IG_API_BASE_URL`·`MARKETING_IG_API_VERSION`으로 바꿀 수 있다. 2026-11-18 서버 읽기 전용 확인 기준 251 서버 설정은 `https://graph.facebook.com` + `v27.0`(Facebook Login 쪽 호스트, 코드 기본값과 다름)이고 - 방침(재헌 확정 2026-11-05): 인공지능기본법 제31조를 적용 대상으로 보고, AI 생성물이면 의무 여부와 상관없이 항상 고지한다. 사람이 보는 문구(캡션·오버레이)와 기계판독 표시를 함께 둔다. 계정 프로필 라벨은 사람이 확인한다.
- 오버레이: `python -m marketing_agent.sns_label <원본> <out_dir> --model <생성 모델 id>` 또는 `sns_label.apply_label()`. ffmpeg `drawtext`로 문구를 입혀 `<out_dir>/labeled.jpg|mp4`, `meta.json`(`ai_label` 키: 문구, 원본·결과 sha256, 설정 파일 sha256, 생성 모델·시각)을 만들고 원본은 보관한다(`raw.*`). 영상은 전 구간 표시, 이미지는 오버레이 뒤 JPEG다. ffmpeg·ffprobe가 없거나 한글 글꼴을 못 찾으면 `LabelError`로 거절하고 라벨 없는 파일을 만들지 않는다.
- 설정: `src/marketing_agent/sns_label.toml` 한 곳(문구·위치·크기·표시 시간·글꼴·화질). `MARKETING_SNS_LABEL_CONFIG`로 다른 파일, `MARKETING_SNS_LABEL_FONT`로 글꼴 지정. 글꼴 선택 순서는 환경변수 → toml `file` → 번들 Pretendard Bold(`src/marketing_agent/assets/fonts/`, SIL OFL 1.1) → 시스템 Nanum/Noto이고 Pillow는 쓰지 않는다. `generate_media` 결과를 한 번에 초안까지 잇는 skill은 `prepare_sns_post_from_media`(`sns_prepare.py`, 게시는 하지 않고 `publish_sns` 사람 승인으로만). **오버레이·메타 문구는 종류별(`[text]`의 `image`·`video`·`unknown`)로 `sns_label.toml`에서 정하고, 기본값은 재헌 확정(2026-11-12) "생성형 AI로 만든 이미지"·"생성형 AI로 만든 영상"·(종류를 모를 때) "생성형 AI로 만든 이미지/영상"이다. 같은 문구가 이미지 XMP(`catbooks:ai_label_text`)와 MP4 `description` 태그에도 들어간다. 변호사 자문은 반영됐다고 재헌이 전했고(서면 확인 별도) 자문서는 이 레포에 없어 `[확인 필요: 서면 보관]`이며, 크기·위치는 서면 확인 전까지 임시값이다. 캡션 안내문(`sns.py`)은 별개이며 이 변경에서 바꾸지 않았다. 문구에 쓴 글자가 글꼴에 없으면 `font_glyph_missing`으로 거절한다(번들 Pretendard Bold 전체판은 한글 11,172자를 가진다. 예전 Std 판은 한글이 없어 교체했다).**
- 기계판독 표시: 이미지는 XMP(`ai_generated=true`, 생성 모델, 시각, IPTC `trainedAlgorithmicMedia`), 영상은 MP4 메타데이터 태그. 외부 모델이 넣은 SynthID·C2PA는 재저장(이 오버레이 포함)하면 사라질 수 있어 대신하지 않는다. 시행령 제23조의 "기계가 판독할 수 있는 방법"으로 인정되는지(표준 규격 포함)는 변호사 확인 필요.
- 환경변수: `MARKETING_MEDIA_DIR`(미디어 폴더, 자산 경로는 이 안쪽만), `MARKETING_SNS_DRAFT_DB`(초안 SQLite 파일, 비우면 메모리).

### 기획안 자동 넘김 (`brief_auto_handoff.py`)

받은 기획안(`receive_campaign_brief`)은 저장만 하고 넘기기는 화면 버튼이 불러야 했다. 서버 안 루프가 아직 안 넘긴 기획안(넘김 기록 없음·`failed`)을 찾아 기존 `handoff_brief_to_sns`를 `media_kind=auto`로 부른다(SNS 글 초안 + 미디어 요청 초안, 멱등 `already_handed`).

- 자동은 초안까지다. 미디어 생성(`prepare_brief_media`→`generate_media`, B등급 관문·건당/월 상한·단가표 fail-closed)과 게시(`publish_sns`, C등급 사람 승인)는 부르지 않는다.
- 실패(`failed`, 가격표 없음 등)는 재시도 간격 뒤 다시 하고 한도(기본 3번)에서 포기한다. 포기해도 화면 버튼으로 넘길 수 있다.
- 환경변수: `MARKETING_BRIEF_AUTO_HANDOFF`(기본 꺼짐, `1`·`true`·`on`), `MARKETING_BRIEF_AUTO_HANDOFF_POLL_S`(60, 0이면 루프 없음), `..._RETRY_S`(300), `..._MAX_ATTEMPTS`(3). 매 주기 다시 읽는다.

### 기획안 미디어 만들기 (`prepare_brief_media`, `brief_media.py`)

화면 SNS·미디어 탭의 "미디어 만들기" 버튼이 부른다(dashboard-api `POST /api/dashboard/marketing/briefs/{proposal_id}/media`).

- 입력은 기획안 번호뿐이다. 종류·장면 템플릿·필드·규격은 `handoff_brief_to_sns`가 보관한 미디어 요청 초안에서 읽어 기존 `prepare_sns_post_from_media`를 그대로 부른다(생성 B등급 관문·우리 키 월 사용량 예산 → 규격 변환 → AI 라벨 → 초안 → 점검). 예산·안전 규칙은 바꾸지 않는다.
- 게시(`publish_sns`, C등급 사람 승인)는 부르지 않는다.
- 비용 전에 거절: 넘기지 않음(`not_handed`), 미정 필드(`fields_missing`), 캐러셀(`carousel_items_undecided`: 장마다 장면을 사람이 정해야 한다), 배경음 모드의 영상(`bgm_fields_required`).
- 멱등: `context_id`를 `ctx_brief_<기획안 번호>`로, 생성 묶음 id를 요청 초안의 `media_ref`로 고정해 같은 요청 초안은 누가 다시 불러도 생성 장부에서 재생된다. 준비된 초안이 있으면 `already_prepared`, 만드는 중이면 `in_progress`.
- 결과는 넘김 기록의 `prepared`에 남고 `list_campaign_briefs`·`get_campaign_brief`의 `sns_handoff.prepared`로 읽는다. 요청 초안(종류·필드)이 바뀌면 보이지 않는다.
- 영상 소리 선택(`choose_brief_audio`, dashboard-api `POST .../briefs/{proposal_id}/audio` 본문 `{choice: keep|bgm, confirmed_listened?}`): 영상을 1회 만든 뒤 확인 단계에서 사람이 한 번 정한다. `keep` "이 영상 그대로 사용"은 결정만 `prepared.audio.decision`에 남긴다(비용 없음). `bgm` "배경음악 따로 만들기"는 영상은 같은 장부 키라 재생(비용 없음)하고 BGM 한 곡만 새로 만들어 영상 소리를 대체한 뒤 AI 라벨·점검을 다시 한다(`generate_media_flow`를 설정만 `bgm_overlay`로 바꿔 한 번 부른다: B등급 관문 우리 키 월 사용량 예산(곡) 그대로, 보류·실패면 결정을 남기지 않는다). 결정은 한 번뿐(`audio_already_decided`)이고 게시 요청이 이미 있으면 거절(`publish_already_requested`)하며, 공급자 소리가 든 영상은 결정이 있어야 게시 요청이 열린다(`audio_decision_required`). `sns_handoff.media_estimate.bgm`에 BGM 추가 사용량(1곡) 조회가 들어간다. 소리를 둔 방식(`audio.mode=source`)으로 만든 영상만 BGM 선택이 된다.
- `sns_handoff.media_estimate`: 조회 때 `plan_cost`(=`generate_media`와 같은 모델 설정·월 예산 규칙)와 장부의 이달 사용량으로 계산한 예상 사용량(`usage`)과 이번 달 예산(`quota`: 사용량·예산·남은 %). 저장하지 않으며 계산할 수 없으면 이유 코드만 준다.
- 미리보기는 dashboard-api `GET .../media/preview`가 `MARKETING_MEDIA_DIR`의 `labeled.jpg|mp4`(AI 라벨을 입히고 점검한 파일, sha256 일치)만 내준다. dashboard-api와 마케팅이 같은 `MARKETING_MEDIA_DIR`을 봐야 한다.

### 기획안 게시 요청 (`request_brief_publish`, `brief_publish.py`)

화면의 "게시 요청" 버튼이 부른다(dashboard-api `POST /api/dashboard/marketing/briefs/{proposal_id}/publish-request`, 본문 없음).

- 입력은 기획안 번호뿐이다. 초안 id·파일 참조·해시·캡션·종류는 서버가 넘김 기록의 `prepared`(지금 요청 초안으로 만든 것)와 SNS 초안 저장소에서 읽는다(초안과 어긋나면 `draft_changed`). 요청 직전에 `check_sns_post`를 다시 돌려 통과한 값만 보낸다.
- 기존 `publish_sns`를 그대로 부른다: C등급, 항상 사람 승인(승인 대기 10분 만료). 사람이 승인 화면에서 진행을 눌러야만 기존 구독자·폴링이 Instagram 게시로 잇는다. 이 skill은 승인하지 않고 만료를 늘리지 않는다. 24시간 게시 상한(45)·중단 상태·어댑터 설정 확인도 `publish_sns` 안에서 그대로다.
- 캐러셀은 범위 밖(`media_kind_unsupported`). 막는 이유 코드: `not_handed`·`not_prepared`·`check_not_passed`·`draft_missing`·`draft_changed`.
- 멱등: `context_id`를 `ctx_brief_<번호>`로 고정하고 내용 해시가 키에 들어간다. 이미 대기·게시·거절된 건은 `already_requested`와 상태만 돌려주고 `publish_sns`를 다시 부르지 않는다. 거절·만료된 건은 같은 키라 다시 요청할 수 없다(새 초안이 필요).
- 조회의 `sns_handoff.publish`: `status`(`not_requested`·`held`·`publishing`·`published`·`rejected`(사람 거절, `rejected_cause`: `human`·`unknown`=옛 기록)·`expired`(승인 마감 만료)·`failed`·`unknown`)·`can_request`·`can_retry`·`caption` 등. 카드 안 승인 패널용으로 `expires_at`(안전 관문 보류 건의 마감, 생성 직후와 폴링 때 `GET /api/safety/reviews/{id}`로 읽어 적어 둔 값)·`preview_url`·`preview_kind`·`ai_label`·`proposal_id`도 준다. 승인 대기 저장소에서 읽은 값만 쓴다.
- 거절과 만료는 `failure_code`로 구분해 기록한다: `review_rejected`(사람 거절, `result.cause=human`) · `review_timeout`(마감 만료, 안전 관문이 `system`으로 자동 거절하거나 폴링이 `expired`를 봄). 구분을 못 하던 옛 기록은 `rejected`+`rejected_cause=unknown`으로 두고 재요청하지 않는다.
- 사람 재요청 `retry=true`(같은 skill, dashboard-api는 같은 경로의 `?retry=true`): 마감 만료(`review_timeout`)로 닫힌 건만 새 멱등 키(`...:r<시도 번호>`)로 `publish_sns`를 다시 부른다. 항상 승인 대기로만 만들고 자동 승인은 없다. 거부 코드: `retry_not_expired`·`retry_rejected_by_human`·`retry_cause_unknown`·`retry_already_published`(같은 내용이 이미 게시)·`retry_other_held`(다른 승인 대기 있음). 24시간 상한·AI 표시·점검 재실행은 그대로다.

### 장애 초안 이미지·게시 요청 (`prepare_outage_sns_media`·`request_outage_sns_publish`, `outage_sns_media.py`)

카드의 "이 초안으로 진행"을 사람이 한 번 누르면 화면이 두 skill을 차례로 부른다(dashboard-api `POST /api/dashboard/marketing/outage-sns-drafts/{post_draft_id}/media`, `.../publish-request`, 미리보기 `GET .../media/preview`). 그 뒤 같은 카드의 승인 패널에서 사람이 이미지·최종 캡션을 보고 승인해야(두 번째 사람 결정) 게시된다. 첫 클릭은 게시 권한이 아니라 이미지 생성 진행 확인이다.

- 입력은 초안 id뿐. 장면 템플릿 `cat_apology_image`(사람·아동·실존 인물 없음, 글자 없음)와 필드(`color_theme=soft pastel`)는 코드 고정값이다.
- 초안 캡션은 바꾸지 않는다. 이미지를 붙인 사본을 새 초안으로 저장한다(`media_from`=원본 id). 게시 대상은 사본이고 목록에서는 원본 카드의 `media_flow`로 보인다.
- 생성은 `generate_media_flow` 그대로(B등급·건당 상한·월 상한·단가표 fail-closed). `context_id`·생성 묶음 id는 초안 id에서만 정해(`ctx_outage_<초안 id>`) 끝난 생성은 장부에서 재생된다(비용 재발생 없음).
- 진행 불가(비용 전 거절): `already_merged`·`publish_history`·`check_failed`·`video_not_supported`·`not_outage_draft`·`draft_not_found`. 병합은 사본이 있는 원본을 건너뛴다.
- 게시 요청의 상태·재시도·`already_requested`는 `brief_publish`의 `state_from_chain`·`submit_publish`를 일반화해 재사용한다. 자동 승인·승인 우회·만료 연장은 없다.
- 영상은 이번 범위 밖(이미지만).

### 사람과 직접 대화 (`chat.py`, `chat_store.py`)
- 화면 경로: dashboard-api `/api/dashboard/marketing-chat` (GET 목록, GET `/{id}`, POST `{thread_id?, message}`, POST `/{id}/close`). 사람 토큰(`Authorization: Bearer`)이 있어야 읽기도 된다.
- 조회·설명만 한다. 읽는 값은 받은 기획안·게시 중인 공지·쿠폰 지급 건수뿐이고, 숫자는 저장소 값을 그대로 인용한다. 캠페인 시작·취소, 공지 게시, 쿠폰 지급을 하라는 말에는 "대화로는 못 한다"는 안내만 한다(모델을 부르지 않음). 대화로 일이 생기지 않으므로 `task_id`는 항상 `null`이다.
- 받은 기획안 본문·메모와 대화 글은 LLM 입력의 `untrusted` 데이터 블록에만 넣는다. 고객 원문·구매자 번호는 싣지 않는다.
- LLM은 `MARKETING_LLM_*`(없으면 `LLM_*`). 없으면 `llm_not_configured`(화면에서는 409 `LLM_NOT_CONFIGURED`)로 거절하고 답을 지어내지 않는다.
- 저장: SQLite, 파일은 `MARKETING_CHAT_DB`(run_all.sh는 `.data/marketing_chat.db`). 비우면 메모리. 열 수 없으면 시작 때 실패한다. 다시 시작하면 `answering`에 멈춘 대화는 풀린다.
- 상태: `talking` · `answering`(AI 답 만드는 중) · `closed`. 30분 동안 말이 없으면 목록·상세를 읽을 때 `closed`로 끝낸다(요약은 마지막 답의 한두 줄 요약, 없으면 첫 질문 일부).
- 열람: 본인(`who` 같음)은 원문 전부, 남의 대화는 `messages: []`+요약+`restricted: true`, 남의 대화에 쓰기는 `forbidden`(403). **지금은 사람별 토큰이 없어 모든 요청자가 같은 "공용"이라 실제로는 막히지 않는다.** 사람별 토큰으로 나뉘면 서버에서 그대로 걸린다. 담당·관리자의 요약 열람은 화면이 맡고 서버는 인사 AI(#662)와 같이 따로 구분하지 않는다.

## 4. 의존
`ax-contracts`, `ax-agent-template`. 다른 부서 폴더를 import하지 않는다.
## 5. 하지 않는 것
- 상태를 바꾸는 일을 `execute()` 없이 하지 않는다
- 보상 대상·단가 판정, 현금 환불은 하지 않는다 (고객지원 소관)
- 금액 교차검증·등급 판정은 하지 않는다 (안전 관문 코드 규칙이 맡고 요청 값은 믿지 않는다. 재무는 끝난 금액만 장부에 적는다)
- 장애 원인을 공지에 적지 않는다 (원인은 infra 판정, 공지는 사실 필드만)
  - 예외는 `draft_outage_sns_post`(장애 사과·보상 SNS 글 초안)뿐이다: 총괄이 넘긴 원인 코드로 고정 문장만 쓰고, 원인으로 본 업데이트를 되돌려 복구가 확인된 경우에만 원인을 말하며 그 밖에는 "원인 확인 중"이라고 쓴다. 영향 숫자는 여기서도 적지 않는다
- 영향 숫자(실패 건수·피해 금액)를 계산하지 않는다 (data 소관)
- 외부 입력(`untrusted`)을 지시로 해석하지 않는다
