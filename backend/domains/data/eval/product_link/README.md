# 소재 ↔ 상품 연결 보정셋 (content_recommend 상품 연결 기준값)

data `content_recommend`가 급상승 소재를 회사 상품에 이을 때 쓰는 임베딩 유사도 기준(`trends.toml` `[recommend] min_similarity`)과 "다른 상품보다 뚜렷이 가까운가"(여유) 기준을 정하는 보정셋이다. 평가 정의라서 기능 코드와 따로 둔다.

```bash
cd backend
# 사람이 한 번만 (run_all.sh로 서버를 띄운 상태, 외부 호출: 인기 검색어 피드 1번 + 임베딩 2번)
uv run python domains/data/eval/product_link/collect.py
uv run python domains/data/eval/product_link/make_cases.py   # 정답·나눔 (네트워크 없음)
uv run python domains/data/eval/product_link/score.py        # 기준표 (네트워크 없음)
uv run pytest -q domains/data/tests/test_product_link_eval_cases.py   # 약속 검사
```

## 폴더

| 파일 | 내용 |
| --- | --- |
| `rules.py` | 정의: 질의 만드는 규칙, 무관 소재 거르기, 글 모양(basic·rich). 네트워크 없음 |
| `collect.py` | 재료 모으기. **사람이 한 번만** 돌린다. shop-api 상품, 인기 검색어 피드, YouTube 스냅샷, 임베딩 |
| `catalog.json` | 회사 상품 8개 (id·이름·카테고리 코드·이름·설명). 2026-11-03 shop-api |
| `topics.json` | 질의·소재 42개 (글, 종류, 만든 근거, 근거 글 개수) |
| `sims/basic.json`, `sims/rich.json` | 글 모양별 소재 × 상품 코사인 (소수 넷째 자리). 벡터와 근거 글은 저장하지 않는다 |
| `make_cases.py` → `cases.json` | 정답(이어야 할 상품)과 나눔(dev·holdout) |
| `score.py` | 채점과 기준 고르기 |

근거 글(YouTube 제목·뉴스 제목)은 남의 글이라 커밋하지 않는다. `topics.json`에는 개수만 남기고, rich 모양 코사인은 모을 때 한 번 계산해 숫자만 남긴다.

## 질의 만드는 법 (`rules.py`)

- **관련 질의 (20개)**
  - 상품마다 이름 핵심어 + 꼬리말 2개("{} 추천", "{} 리뷰")로 16개를 만든다. 핵심어는 숫자가 든 낱말과 "세트"를 뺀 이름이다. 예: "무지 노트 3권 세트" → "무지 노트 추천".
  - 카테고리 이름 + 꼬리말 2개("{} 추천", "{} 신상")로 4개를 만든다(도서·문구).
- **무관 소재 (22개)**
  - 지금 인기 검색어(피드) 앞에서 최대 20개를 넣는다. 오늘 피드에는 10개뿐이었다.
  - 최신 YouTube 인기 스냅샷 태그 중 영상 2개 이상인 것을 영상 수 순으로 12개 넣는다. 회사 수동 제외 목록에 있는 태그는 뺀다.
  - 상품 핵심어의 낱말(2글자 이상)이나 카테고리 이름이 들었거나, 소재 이름이 상품 이름 안에 들면 뺀다. 오늘은 뺀 것이 0개였다.
- **글 모양**
  - basic(지금 content_recommend와 같다): 소재 = 이름, 상품 = "이름 (카테고리)".
  - rich: 소재 = 이름 + 근거 글 최대 3개(YouTube 소재는 그 태그 영상 제목, 인기 검색어는 피드의 뉴스 제목), 상품 = "이름 (카테고리)" + 설명(있으면).

## 정답 (`make_cases.py`, 순환 논리 금지)

정답은 **질의를 만든 방식에서만** 정한다. 유사도 값이나 그래프를 보고 정하지 않는다.

- 이름 질의는 그 상품 하나, 카테고리 질의는 그 카테고리 상품 전부가 정답이다.
- 무관 소재는 이을 상품이 없다.
- 나눔: `sha256("2026110302:<소재 id>") % 10 < 3`이면 holdout이다. dev 30개(관련 13, 무관 17), holdout 12개(관련 7, 무관 5)다. holdout은 고른 설정의 숫자만 본다.
- seed를 `2026110301`에서 `2026110302`로 바꿨다. 처음 만든 뒤 케이스 목록을 출력하면서 holdout 케이스 내용을 봤기 때문이다(`eval/README.md` holdout 규칙). 다시 나눈 뒤에는 holdout 개수와 고른 설정의 숫자만 봤다.

## 연결 규칙과 지표 (`score.py`)

- **연결 규칙**: 유사도 높은 순으로 최대 3개(`max_products`)를 보며, 유사도 ≥ `min_sim`이고 여유 ≥ `min_margin`인 상품만 잇는다. 여유는 그 상품 유사도에서 기준값을 뺀 값이고, 종류에 따라 기준값이 다르다.
  - `none`: 여유를 보지 않는다(지금 방식).
  - `top2`: 나머지 상품 중 최고 유사도를 뺀다. 1등만 이을 수 있다.
  - `mean`: 나머지 상품의 평균을 뺀다.
- **지표**
  - 재현율: 관련 질의 중 맞는 상품을 하나 이상 이은 비율
  - 정밀도: 이은 상품 중 정답 비율
  - 무관 오연결률: 무관 소재 중 하나라도 이은 비율
- **기준 고르는 법** (결과를 보기 전에 정했다)
  1. dev에서 무관 오연결률이 0이고 정밀도가 0.9 이상인 설정만 남긴다.
  2. 그중 재현율이 가장 높은 설정을 고른다.
  3. 재현율이 같으면 여유 기준이 큰 것, 그다음 유사도 기준이 큰 것, 그다음 none → top2 → mean 순으로 고른다.
- **살펴본 값**: 유사도 0.30~0.80(0.05 간격), 여유 0~0.15.

## 기준표 (2026-11-03, `gemini-embedding-2`)

basic과 rich는 고른 설정과 지표가 같다(아래 표 하나). rich에서 달라지는 것은 무관 소재의 글뿐이다. 관련 질의는 근거 글이 없고, 상품에는 설명이 없다.

| 설정 | 기준 | dev 재현율 | dev 정밀도 | dev 무관 오연결률 | holdout 재현율 | holdout 정밀도 | holdout 무관 오연결률 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 지금 설정 | none / 유사도 ≥ 0.60 | 1.00 | 0.60 | 0.00 | 1.00 | 0.77 | 0.00 |
| 고른 설정 (none만) | none / 유사도 ≥ 0.70 | 0.85 | 1.00 | 0.00 | 0.57 | 1.00 | 0.00 |
| 고른 설정 (top2만) | top2 / 유사도 ≥ 0.65 / 여유 ≥ 0.00 | 1.00 | 1.00 | 0.00 | 0.86 | 1.00 | 0.00 |
| 고른 설정 (mean만) | mean / 유사도 ≥ 0.65 / 여유 ≥ 0.15 | 0.92 | 1.00 | 0.00 | 0.57 | 1.00 | 0.00 |
| **고른 설정 (전체)** | **top2 / 유사도 ≥ 0.65 / 여유 ≥ 0.00** | 1.00 | 1.00 | 0.00 | 0.86 | 1.00 | 0.00 |

참고(전체 42개)
- 관련 질의의 정답 상품 유사도 최솟값은 0.606이다.
- 무관 소재의 최고 유사도 최댓값은 basic 0.573, rich 0.524다. 근거 글을 붙이면 무관 소재의 유사도가 내려갔다.

읽는 법
- **지금 설정(유사도 ≥ 0.6, 여유 없음)**: 무관 소재는 잇지 않는다. 하지만 관련 질의에 같은 카테고리의 다른 상품까지 붙여 정밀도가 0.60(dev)·0.77(holdout)이다.
- **"1등만"(top2, 여유 0)**: 정밀도가 dev와 holdout 모두 1.0이다. 다른 상품을 잘못 붙이는 문제는 "1등만"으로 풀린다.
- **유사도 기준 0.65**: 고르는 규칙(재현율이 같으면 큰 기준)에 따라 골랐다. holdout 재현율 0.86은 관련 질의 7개 중 1개를 놓쳤다는 뜻이다. 관련 질의와 무관 소재의 유사도 사이가 0.573~0.606으로 좁아서, 기준을 어디에 둘지는 이 보정셋 크기로는 확정하기 어렵다.
- **여유 기준 0 초과**: dev 재현율이 떨어져 고르지 않았다. 관련 질의의 1등과 2등 차이가 작은 경우가 있기 때문이다(카테고리 질의 등).

## 한계

- **작다**: 상품 8개, 소재 42개, holdout 12개(관련 7개)다. 기준값은 이 회사의 지금 상품 목록에 맞춘 값이다.
- **관련 질의가 쉽다**: 질의에 상품 이름 핵심어가 그대로 들어 있어 문자열 일치로도 잡힌다. 뜻만 가까운 질의(예: "그림책 추천")는 만들 규칙이 없어 넣지 않았다. 그래서 임베딩만으로 잇는 경우의 재현율은 이 표보다 낮을 수 있다.
- **rich 비교가 한쪽뿐이다**: 관련 질의에는 근거 글이 없고 상품에는 설명이 없어서, rich는 무관 소재 쪽만 바뀐다.
- **하루치**: 무관 소재는 2026-11-03 피드와 YouTube 스냅샷 하나에서 왔다. 대부분 게임·뉴스라 도서·문구와 아주 멀다.
