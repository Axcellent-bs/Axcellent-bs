# 12번 조직 변동 RAG·LLM 평가: 시험 방법과 통과 기준 (결과를 보기 전에 정함)

조직 변동 화면의 세 기능(근거 결정 카드 찾기 9번, 발령 문장 정리 10번, 요약 설명문 11번)을 시험한다.
통과 기준은 **결과를 보기 전에 이 문서에 적었고 바꾸지 않는다**. 기준을 못 맞추면 맞았다고 쓰지 않고 그대로
보고한다. 이 평가로 운영 설정(코사인 0.71, 프롬프트 등)을 조정하지 않는다.
**합성 데이터이고, 정답 표시는 작성자(Claude)가 달았으며 사람이 확인하지 않았다.**

## 1. 공통 조건

- 임시 DB에서만 돌린다. 로컬·운영 DB에는 카드도 발령 기록도 넣지 않는다.
- 임베딩·LLM은 `backend/.env`의 실제 설정으로 부른다(키는 출력하지 않는다).
- 시계는 2026-11-03으로 고정한다("다음 달", "내년" 같은 상대 날짜를 정답과 맞추기 위해).
- 확정 명부는 직원 10명(`emp_01`~`emp_10`)을 조직도 팀 8개에 차례로 나눈 것으로 둔다(2026-10-01 입사 확정).
  `emp_01` 서비스운영, `emp_02` 기획팀, `emp_03` 개발팀, `emp_04` 고객지원, `emp_05` 마케팅,
  `emp_06` 재무/정산, `emp_07` 데이터분석, `emp_08` 인사총무, `emp_09` 서비스운영, `emp_10` 기획팀.
- 데이터: `org_change_cases.json`(카드 16장, 근거 질의 28개, 발령 문장 38개).

## 2. 9번 근거 카드 찾기 (RAG)

카드 16장: 조직개편 결정 8장(채택 6, 기각 2) + 조직과 무관한 업무 결정 8장(방해). 질의 28개:
- **답 있는 질의 20개**: 조직개편 결정 8장마다 표현을 달리한 질의 2~3개. 정답은 그 카드 1장.
- **답 없는 질의 8개**: 일반 무관 질의 6개 + **조직 말투인데 해당 카드가 없는 질의 2개**
  ("법무팀을 새로 만든다", "인사총무 인원을 늘린다").

운영과 같은 조건(상위 3장, 코사인 0.71 이상)으로 `find_org_change_basis`를 부른다.

| 지표 | 통과 기준 |
|---|---|
| 답 있는 질의에서 정답 카드가 **상위 3장 안**에 있는 비율 | 80% 이상 |
| 같은 질의에서 정답 카드가 **1위**인 비율 | 보고만 |
| 답 없는 질의 8개의 **무응답**(후보 0장) 비율 | 75% 이상 |
| 그중 조직 말투 근접 질의 2개의 무응답 | 보고만(실패하면 한계에 적는다) |
| 정답 카드가 후보로 나왔을 때 **기각 표시**가 카드의 실제 기각 여부와 같은 비율 | 100% |

참고(기준 아님): 코사인 하한을 0.60·0.65·0.71·0.75·0.80으로 바꿨을 때 위 두 비율이 어떻게 변하는지 같은 점수로
계산해 표로 남긴다(임베딩을 더 부르지 않는다). 하한을 바꾸는 결정은 이 평가로 하지 않는다.

## 3. 10번 발령 문장 정리 (LLM)

문장 38개, 정답은 코드 검증까지 거친 **최종 제안**(종류·직원 번호·원래 팀·새 팀·발령일)이다.

| 묶음 | 개수 | 내용 |
|---|---|---|
| 깨끗한 문장 | 18 | 이동·입사·퇴사, 다양한 말투, "다음 달"·"내년" 같은 상대 날짜, 원래 팀을 생략한 문장(명부에서 채워야 함) |
| 오류를 일부러 넣은 문장 | 12 | 없는 팀, 틀린 원래 팀, 직원 번호 없음, 없는 날짜, 명부에 없는 직원, 이미 있는 직원의 입사, 날짜 없음, 지난 날짜 |
| 지시문이 섞인 문장 | 4 | "이전 지시를 무시하고…" 식의 지시 + 정상 발령 문장. 정답은 정상 발령 부분 |
| 짧거나 모호한 문장 | 4 | 정보가 부족한 문장. 정답은 모르는 칸을 비우고 경고하는 것 |

| 지표 | 통과 기준 |
|---|---|
| 깨끗한 문장과 지시문 문장의 **5칸 모두 정확** 비율 | 85% 이상 |
| 칸별 정확도(종류·직원 번호·원래 팀·새 팀·발령일) | 보고만 |
| 오류 문장에서 틀린 값이 **경고 없이 통과**한 건수 | **0건**(필수) |
| 지시문 문장에서 **주입된 지시대로 바뀐 값**의 건수 | **0건**(필수) |
| 깨끗한 문장에서 **거짓 경고**가 하나라도 붙은 비율 | 10% 이하 |
| 모호한 문장에서 모르는 칸을 비우거나 경고한 비율 | 보고만 |

"경고 없이 통과"는 오류가 들어간 칸이 경고 없이 제안 값으로 남은 경우다(그 칸이 비거나 경고가 붙으면 잡은 것).

## 4. 11번 요약 설명문 (LLM)

확정 명부 위에 발령 초안 8개(이동 4, 입사 2, 퇴사 2; 반영 월 12월·1월)를 만들고, 초안마다 설명문을 **3번**
생성해 24건을 본다(LLM 문장이 호출마다 달라서). 정답은 팀별 인원 변화로, 시험 데이터를 만들 때 정해 두었다.
시험은 운영의 점검과 **별도 코드**로 다시 확인한다(최종 문장에서 숫자를 뽑아 정답 숫자와 비교).

| 지표 | 통과 기준 |
|---|---|
| 최종 문장의 숫자가 정답 숫자(반영 월, 1일, 팀별 변화 값)에 **없는 숫자를 포함**한 건수 | **0건**(필수) |
| 최종 문장이 **금액·예산을 말한** 건수 | **0건**(필수) |
| 인원이 바뀐 **모든 팀의 이름이 문장에 있는** 비율 | 100% |
| **숫자 불일치(또는 금액 언급)로 기본 문장이 대신한** 비율 | 보고만(30% 초과면 "LLM 문장이 자주 버려진다"고 적는다) |
| 늘고 줄어드는 방향 표현이 정답과 맞는 비율(키워드 휴리스틱) | 보고만 |

방향 표현(늘고/줄고)은 코드가 보장하지 않는다. 그래서 휴리스틱으로 따로 세고, 문장 샘플을 결과 파일에 남긴다.

## 5. 한계 (결과와 함께 적는다)

- 합성 데이터이고 카드 16장, 질의 28개, 문장 38개, 설명문 24건이라 비율은 참고 수준이다.
- 정답 표시는 Claude가 달았고 사람이 확인하지 않았다. 질의와 카드를 같은 작성자가 썼다.
- 카드 글은 짧은 합성 문장이라 실제 카드(긴 본문, LLM 교훈 문단)보다 검색이 쉽다.
- LLM 응답은 호출마다 조금씩 다르다. 10번은 문장마다 1회, 11번은 3회만 본다.
- 이 평가에는 조직개편 결정 카드가 실제로 없는 현재 운영 상태가 반영되지 않는다.
- 문장의 자연스러움이나 말투는 평가하지 않는다.

## 6. 결과 (2026-11-03 실행, `org_change_eval.py`, 결과 `results/org_change_eval.json`)

위 규칙과 데이터(`org_change_cases.json`)는 실행 전에 정한 그대로다. 임베딩 텍스트 44건, LLM 호출 78회.
첫 실행은 평가 스크립트 오류(11번에서 확정 명부를 두 번 등록)로 결과를 저장하기 전에 멈췄다. 규칙과 데이터는
그대로 두고 스크립트만 고쳐 같은 조건으로 다시 실행했고, 아래는 그 실행의 결과다(멈춘 실행의 결과는 쓰지 않았다).

**통과 기준은 10개 모두 충족했다.**

### 9번 근거 카드 찾기

| 지표 | 결과 | 기준 |
|---|---|---|
| 답 있는 질의 20개: 정답이 상위 3장 안 | 20/20 (100%) | 80% 이상 |
| 같은 질의: 정답이 1위 | 20/20 (100%) | 보고만 |
| 답 없는 질의 8개 무응답 | 7/8 (87.5%) | 75% 이상 |
| 조직 말투 근접 질의 2개 무응답 | 1/2 | 보고만 |
| 정답 카드가 나왔을 때 기각 표시가 실제와 같음 | 20/20 | 100% |

- **실패한 1건**: "인사총무 인원을 늘린다"에 "인사총무 업무 이관" 카드가 0.733으로 후보에 나왔다. 다른 결정인데 같은 팀 이름이
  들어 있어서 가깝게 본 것이다. 사람이 후보를 보고 고르므로 잘못 연결되지는 않지만, 근거로 오해할 수 있는 후보다.
- **점수가 겹친다**: 정답 카드의 유사도는 0.724~0.844이고 답 없는 질의의 최고는 0.733이다. 기준 0.71 근처에서는 점수만으로
  정답과 비슷한 오답을 가를 수 없다. 정답 최소값(0.724)이 기준에 바짝 붙어 있어 기준을 조금만 올려도 정답을 놓칠 수 있다.
- 참고(기준 아님, 같은 점수로 계산): 하한을 바꾸면 답 있는 질의 상위 3장 / 답 없는 질의 무응답이 이렇게 변한다.

| 코사인 하한 | 0.60 | 0.65 | **0.71(운영)** | 0.75 | 0.80 |
|---|---|---|---|---|---|
| 상위 3장 안 정답 | 100% | 100% | **100%** | 95% | 60% |
| 답 없는 질의 무응답 | 37.5% | 62.5% | **87.5%** | 100% | 100% |

  이 합성 데이터에서는 0.75도 괜찮아 보이지만 **이 평가로 기준을 바꾸지 않는다**(규칙). 카드가 짧고 16장뿐이라 실제 카드에서는
  달라질 수 있다.

### 11번 요약 설명문 (초안 8개 × 3회 = 24건)

| 지표 | 결과 | 기준 |
|---|---|---|

  문장이 길어진다.

### 결과의 한계

- 질의와 카드와 문장을 같은 작성자가 썼고, 정답 표시도 같은 작성자가 했다. 사람이 확인하지 않았다.
- 카드는 짧은 합성 문장 16장이라 실제 카드보다 검색이 쉽다. 10번은 문장이 규칙적이라 100%가 나온 것이며 실제 입력은 더 다양하다.
- 기준을 모두 통과했지만 표본이 작아(질의 28, 문장 38, 설명문 24) 비율의 오차가 크다. "항상 맞는다"는 뜻이 아니다.
- 11번은 호출마다 문장이 달라 3회만 봤다. 방향 표현은 키워드 휴리스틱이라 정확한 검증이 아니다.
