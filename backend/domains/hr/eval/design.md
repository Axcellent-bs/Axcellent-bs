# 인사 AI 검색 평가: 골든 셋 설계 (초안)

> 이 평가 데이터는 **합성**이다. 실제 운영 데이터가 아니다. 문서·이력서에서도 "합성 평가 데이터"라고 쓴다.
> 상태: 설계 초안 (사용자 검토 전). 카드·질의 본문은 이 설계가 확정된 뒤에 만든다.

## 1. 목적

검색 방식(기준선 2-gram Dice → Dense → Sparse → Hybrid)을 같은 문제집으로 비교한다. 검색이 쓰이는 기능 세 곳을 기준으로 나눈다.

| 기능 | 어디에 쓰이나 | 카드 종류(`kind`) | 카드 | 질의 |
|---|---|---|---|---|
| A. 계획 점검 | `check_plan`이 새 계획과 비슷한 과거 결정을 찾는다 | `decision`, `policy` | 50 | 45 |
| B. 총괄 이관 | 원인 미확정 이관 때 비슷한 과거 사건을 찾는다 | `incident`, `case`, `fraud` | 40 | 30 |
| C. 인수인계 질문 | 빠진 항목에 맞는 과거 인수인계를 찾는다 | `case`, `notice` | 30 | 25 |
| 합계 | | | **120** | **100** |

## 2. 카드 표기 (기존 `Card` 계약 그대로)

새 필드는 만들지 않는다. 분류 정보는 `tags`와 `extra`에 둔다.

| 필드 | 값 |
|---|---|
| `card_id` | `gold_<기능><군집번호>_<순번>` 예: `gold_A1_03` |
| `tags` | `합성`, 군집 이름 |
| `extra` | `{"synthetic": true, "function": "plan_check|escalation|handover", "cluster": "A1", "domain": "캣북스|일반"}` |
| `author` | `eval-gold` |
| `confidence` | `high` |

- `domain`은 카드 안의 배경이다. 서비스 이름(`shop-api`, `payment` 등)이 나오면 `캣북스`, 아니면 `일반`.
- 실제 카드(`payment` 5xx 결정) 1~2장은 B1에 대표 샘플로 넣는다. 5장이 전부 같은 내용이라 중복은 빼고, 나머지 B1 카드는 날짜·원인·조치가 서로 다른 사건으로 만든다.

## 4. 비슷한 오답 쌍 (일부러 넣는 방해 카드)

같은 질의에서 헷갈려야 방식 간 차이가 보인다. 아래 쌍은 서로 **다른 내용**이어야 하고, 한쪽이 질의의 정답이면 다른 쪽은 정답이 아니다.

| 쌍 | 구분되어야 하는 점 |
|---|---|
| A1 `shop-api` 롤백 ↔ `shop-web` 롤백 | 대상 서비스 |
| A2 금요일 배포 금지 ↔ 이벤트 기간 동결 | 동결 이유와 기간 |
| A3 DB 마이그레이션 결정 ↔ B8 커넥션 풀 고갈 | 계획 결정 vs 장애 사건 |
| B1 결제 5xx ↔ B2 결제 지연 | 오류 종류 (오류율 vs 응답 시간) |
| B3 주문 타임아웃 ↔ B2 결제 지연 | 원인 서비스 |
| B6 쿠폰 중복 발급 ↔ A7 쿠폰 공지 정책 | 사건 vs 정책 |
| C2 퇴사 인수인계 ↔ C3 부서 이동 인수인계 | 퇴사는 연락 불가, 이동은 문의 가능 |
| C1 당직 교대 ↔ C5 진행 중 장애 인수인계 | 일상 교대 vs 진행 중인 사건 |

## 5. 질의 설계 (100개)

각 기능 안에서 아래 비율을 유지한다.

| 유형 | 비율 | 예시 방향 | 개수 |
|---|---|---|---|
| 표현이 다른 질의 | 40% | 카드에 없는 단어로 같은 뜻을 묻는다 ("결제가 자꾸 실패해요") | 40 |
| 식별자·키워드 질의 | 20% | 서비스명, 에러 코드, 사건 번호 | 20 |
| 길고 섞인 질의 | 20% | 사건 설명 + 계획 문장 (`check_plan` 실제 입력 형태) | 20 |
| 정답 없음 | 20% | 코퍼스에 없는 주제 (연말정산, 사무실 이전, 면접 일정, 법인카드 한도, 출장 규정 등) | 20 |

- 정답은 **카드 id 목록**(한 개 이상). 정답 없음 질의는 빈 목록.
- 한 질의에 정답 카드가 둘 이상일 수 있다 (같은 군집의 비슷한 카드).
- 질의 본문은 카드 문장을 그대로 복사하지 않는다.

## 6. 분할

- 개발용 30(기준값 `MIN_COSINE` 조정 전용) / 평가용 70(최종 수치 보고 전용). 기능·유형 비율이 같게 층화해서 나눈다.
- 같은 질의로 기준값을 조정하고 같은 질의로 점수를 내지 않는다.

## 7. 지표

| 지표 | 정의 |
|---|---|
| Recall@5 | 정답이 있는 질의 중 상위 5개에 정답 카드가 하나라도 있는 비율 |
| 인용 정확도 | 정답이 있는 질의의 상위 결과 중 정답 카드의 비율(평균) |
| 관련 없음 정확도 | 정답 없음 질의에서 결과가 0건인 비율 |
| 응답 시간 | 질의당 평균·최대 (임베딩 포함 시) |

## 8. 거짓 오답 방지

- 방해 카드가 정답 카드와 사실상 같은 내용이면 검색이 맞혀도 틀린 것으로 채점된다. 같은 군집 카드는 **날짜·원인·조치·담당 중 둘 이상이 서로 달라야** 한다.
- 질의를 확정할 때 "이 질의에 정답이 될 수 있는 다른 카드"가 없는지 군집 단위로 다시 확인한다.

## 8-1. 검색 풀 (질의를 만들며 정한 것)

질의는 **같은 기능의 카드 풀 안에서만** 검색한다(계획 점검 50장, 총괄 이관 40장, 인수인계 30장). 실제 기능도 종류별로 거르고 검색하고, 다른 기능 카드가 섞이면 정답이 아닌 비슷한 카드가 늘어 라벨이 모호해진다. `queries.json`의 `pool` 필드가 이를 나타낸다. 1000장 확장 때는 방해 카드를 각 풀에 더한다.

## 9. 사용자에게 확인받을 것

1. 군집(A1~A10, B1~B9, C1~C7)과 장 수가 맞는가. 빠졌거나 어색한 주제가 있는가.
2. 비슷한 오답 쌍(4장)에 더할 것이 있는가.
3. 정답 없음 주제(5장 예시)를 더 늘릴 것인가.
