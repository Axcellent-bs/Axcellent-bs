# holdout(훈련용·테스트용 분리) 시험: 방법과 판정 기준 (결과를 보기 전에 정함)

2026-11-10, 이태윤 님의 요청("각각의 a2a에 holdout 테스트")에 따라 인사 AI에서 한다.
holdout은 전체 데이터를 **훈련용(Train)** 과 **테스트용(Test)** 으로 나눠, 훈련용으로만 값을 정하고 테스트용으로 성능을 재는 방법이다.
이 문서의 기준은 결과를 보기 전에 적었고 바꾸지 않는다.

## 1. 무엇을 시험하나 (인사 AI에서 데이터로 정하는 값)

| 시험 | 데이터로 정하는 값 | 코드 |
|---|---|---|
| A. 과거 사례 검색 | 코사인 하한, 상대 기준 컷 δ (**채택된 V3** = V2 + LLM 검증. 이 문서를 처음 쓸 때 V2로 잘못 적었고 11/10에 고쳤다) | `refine_eval.py` |
| B. 카드 병합 판정 | 코사인 하한 `T_low`, 자동 병합 `T_auto` | `link_eval_v2.py` |

- 총괄 AI와 에이전트 평가 판정은 **데이터로 정하는 값이 없어** 이번 시험에서 뺀다. 총괄은 규칙 기반이고, 에이전트 평가의 30초 기준은 총괄 코드의 호출 마감에서 온 값이지 데이터로 맞춘 값이 아니다.

## 2. 분리

| 시험 | Train (값을 정함) | Test (처음 값을 잰 뒤 고정) | 비고 |
|---|---|---|---|
| A | 개발용 질의 33개 | 평가용 질의 67개 | 카드 620장(골든 120 + 방해 500) 공통 |
| A 검증 | (같은 Train) | 검증용 질의 40개 (`queries_holdout.json`) | 8-2에서 한 번 평가했으므로 **두 번째 사용**이다. 처음 보는 데이터가 아니다 |
| B | 개발용 토픽 쌍 76개 | 새 평가용 토픽 21~30의 쌍 32개 | 결정 문장만 비교 |

- 값은 항상 Train으로만 정하고, Test와 검증용 결과를 본 뒤 값을 다시 고르지 않는다.
- Test에서 성능이 나빠도 값을 고치지 않고 그대로 보고한다.
- 모든 데이터는 **합성**이고 정답 라벨은 Claude가 정했다(사용자 확인 전).

## 3. 판정 기준

과적합 여부를 **Train 대비 Test의 하락 폭**으로 본다.

A (과거 사례 검색, V3):
1. 정답 질의의 Recall@1이 Train 대비 Test에서 **5%p 넘게 떨어지지 않는다**.
2. 정답 없는 질의의 "관련 없음 정확도"가 Train 대비 Test에서 **10%p 넘게 떨어지지 않는다**. (Train이 작아 100%이므로 Test가 90% 미만이면 미달)
3. 검증용 40개에서 정답 있는 20개 중 1위 정답이 **17개 이상**이고, 정답 없는 20개 중 무응답이 **17개 이상**이다.

B (카드 병합):
4. 같은 주제 판단 정확도가 Train 대비 Test에서 **5%p 넘게 떨어지지 않는다**.
5. Test에서 **잘못 병합이 0건**이다 (서로 다른 결정을 같은 것으로 자동 병합하지 않음).

## 4. 보고

기준 통과 여부와 상관없이 Train·Test(·검증용) 결과를 모두 적는다. 미달이면 "미달"이라고 쓰고 운영 코드와 기준값은 바꾸지 않는다.
이전 실행 결과(`results/*.json`의 10월 말 기록)와 이번 실행을 비교해, 같은 코드·같은 데이터에서 재현되는지도 적는다.
임베딩 API 한도(무료 하루 1000건)에 걸리면 그 시점에서 멈추고, 못 돌린 부분은 "못 했다"고 적는다.

## 5. 결과 (2026-11-10)

**11/10에 처음 시도했을 때** 임베딩 API 하루 무료 한도(429)에 걸려 필요한 벡터 760건 중 608건에서 멈췄다.
키를 새로 받은 뒤 같은 날 `refine_eval.py dev|test|holdout`와 `link_eval_v2.py`를 처음부터 끝까지 다시 돌렸다(벡터 760건 모두 받음).
**결과는 10월 말 저장 결과와 모든 수치가 같았다**(기준값 0.7063·0.7094·δ 0.05·`T_low`·`T_auto` 포함). 아래 표는 이번 실행의 값이다.

재현 범위 (무엇을 다시 확인했고 무엇을 못 했나):

| 부분 | 이번에 새로 확인한 것 | 확인하지 못한 것 |
|---|---|---|
| 검색 V0~V2 (임베딩, 기준값) | 벡터를 새로 받아 계산, 10월과 동일 | |
| 검색 V3 (LLM 검증) | 임베딩과 상위 후보 계산은 동일 | **LLM 판정 108건은 저장해 둔 것을 재사용했다(Claude 호출 0회).** LLM이 같은 판정을 다시 내리는지는 보지 못했다 |
| 카드 병합 | Claude를 29번 실제로 다시 불러 판정, 10월과 동일 | |

### A. 과거 사례 검색 (카드 620장, 기준값은 개발용으로만 정함)

| 구분 | 질의 | Recall@1 | 정답 없는 질의 무응답 | 인용 정확도 |
|---|---|---|---|---|
| Train (개발용) | 33 | 88.5% (23/26) | 100% (7/7) | 86.5% |
| Test (평가용) | 67 | 94.4% (51/54) | 100% (13/13) | 94.4% |
| 검증용 (두 번째 사용) | 40 | 100% (20/20) | 95% (19/20) | 100% |

### B. 카드 병합 (`T_low` 0.8184, `T_auto` 0.9101, 개발용으로만 정함)

| 구분 | 쌍 | 같은 주제 판단 정확도 | 잘못 병합 |
|---|---|---|---|
| Train (개발용) | 76 | 100% | 0 |
| Test (새 토픽 21~30) | 32 | 96.9% | 0 (자동 병합 6쌍, 사람 승인 4쌍) |

### 기준별 판정 (11/10 재실행 결과 기준)

| 기준 | 결과 | 판정 |
|---|---|---|
| 1. Recall@1 하락 5%p 이내 | Train 88.5% → Test 94.4% (하락 없음) | 충족 |
| 2. 무응답 정확도 하락 10%p 이내 | 100% → 100% | 충족 |
| 3. 검증용 1위 정답 17개 이상, 무응답 17개 이상 | 20/20, 19/20 | 충족 |
| 4. 병합 정확도 하락 5%p 이내 | 100% → 96.9% (3.1%p) | 충족 |
| 5. 테스트 잘못 병합 0건 | 0건 | 충족 |

### 한계 (결과보다 중요하다)
- **기준을 결과를 모르는 상태에서 적지 않았다.** 이 문서의 기준은 10월 말 수치를 이미 알고 있는 상태에서 오늘 적었다. 사전 등록이 아니다.
- **검증용 40개는 처음 보는 데이터가 아니다.** 8-2에서 V3를 고르는 데 이 40개의 결과를 썼으므로(V3의 무응답 19/20이 채택 근거), V3에 대해서는 깨끗한 holdout이 아니다. 개발용·평가용 67개도 7·8번 비교와 8-2 설계에서 이미 본 질의다.
- 기준값(코사인 하한, δ, `T_low`, `T_auto`)을 개발용으로만 정한 점은 지켰다. 이 부분의 Train→Test 비교는 유효하다.
- 평가용 Recall@5는 V3에서 98.2% → 94.4%로 내려갔다(LLM이 1위가 아닌 정답 카드를 관련 없음으로 판정).
- 모든 데이터는 합성이고 정답 라벨은 Claude가 정했다(사용자 확인 전). 질의 수가 적어(정답 없는 질의 7·13·20개) 한 건이 5~14%p를 움직인다.
- **처음 보는 새 데이터로 한 번 더 재려면** 새 질의 40개를 만들어 한 번만 평가해야 한다.
