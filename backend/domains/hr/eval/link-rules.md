# 15번 카드 연결 Dense 전환과 중복 병합: 시험 방법과 채택 기준 (결과를 보기 전에 정함)

새 결정 카드가 예전 결정 카드와 "같은 주제"인지 판단하는 부분(지금은 글자 겹침 Dice 0.5)을 Dense로 바꾸고,
같은 결정을 다시 쓴 중복 카드를 묶는다. 확신이 매우 높은 구간만 AI가 자동으로 병합하고 나머지는 사람이 승인한다.
채택은 이 문서의 기준으로만 정한다. 기준은 결과를 보기 전에 적었고 바꾸지 않는다.
**데이터는 합성이고 정답 라벨은 작성자(Claude)가 정했다(사용자 확인 전).** 운영 성능이 아니다.

## 1. 데이터 (`link_pairs.json`)

결정 문장 토픽 20개. 토픽마다 기준 결정(`orig`)과 세 가지 새 문장이 있다.

| 라벨 | 뜻 | 예 |
|---|---|---|
| `duplicate` | 같은 결정을 다른 말로 다시 씀 | "배포는 평일 10~16시" vs "서비스 배포 시간은 평일 10시부터 16시까지로 한정한다" |
| `update` | 같은 주제의 결정을 바꿈(숫자·조건이 바뀜) | 같은 배포 시간 결정을 "오후 6시까지, 긴급 수정은 제한 없음"으로 바꿈 |
| `related` | 같은 영역이고 관련은 있지만 다른 결정 | "배포 전 스테이징에서 30분 부하 시험" |
| `unrelated` | 같은 영역의 다른 토픽 기준 결정끼리 | 배포 시간 결정 vs 백업 시각 결정 |

- 쌍은 (새 문장, 옛 카드 = 기준 결정)이다. 연결 판단은 같은 영역 안에서만 하므로 `unrelated`도 같은 영역의 다른 토픽 쌍이다.
- 토픽 1~10 = **개발용**(기준값 정함), 11~20 = **평가용**(마지막에 한 번만 평가). 두 구간에 걸치는 `unrelated` 쌍은 쓰지 않는다.
- 카드는 `record_case`로 만든 결정 카드(`kind=decision`, 채택)이고 임베딩은 운영과 같은 방식(카드 제목+본문, 질의는 새 문장)이다.

## 2. 시험 1: 연결 판단(같은 주제인가) Dice vs Dense

- 정답: `duplicate`·`update` = 같은 주제(대체 후보), `related`·`unrelated` = 다른 결정.
- Dice(현재): 유사도 0.5 이상이고 문장이 다르면 같은 주제. 개발용에서 정확도가 가장 높은 값으로 조정한 Dice도 참고로 같이 본다.
- Dense: 코사인 하한 `T_low`. 개발용 쌍의 코사인 전부를 후보로, 개발용 정확도가 가장 큰 값들의 **가운데 값**(8-2와 같은 방식)을 쓴다.
- 지표: 평가용 정확도, 정밀도(같은 주제라고 한 것 중 맞은 비율), 재현율.
- **채택 기준**: 평가용에서 **Dense 정확도 ≥ Dice(0.5) 정확도**. 낮으면 Dense로 바꾸지 않고 결과를 그대로 보고한다.

## 3. 시험 2: 자동 병합 구간

중복(`duplicate`)만 병합 대상이다. `update`는 병합이 아니라 기존의 대체(supersede) 규칙으로 간다.

- 병합 정책: 코사인 ≥ `T_auto` **그리고** LLM이 "같은 결정"이라고 판정 → AI가 자동 병합(원래 카드는 지우지 않고 대체됨 표시, 복원 가능).
  `T_low` 이상이지만 자동 조건을 못 채우면 사람이 승인하는 후보 목록에 올린다.
- `T_auto` = 개발용에서 `duplicate`가 아닌 쌍(`update`·`related`·`unrelated`)의 **가장 큰 코사인 + 0.005**.
  이 값 이상인 개발용 `duplicate`가 하나도 없으면 자동 구간을 열지 않는다(전부 사람 승인).
- LLM 판정: 평가용 쌍 중 코사인이 `T_low` 이상인 것에만 한 번씩, 3가지 중 하나(같은 결정을 다시 쓴 것 / 내용이 바뀐 것 / 별개의 결정).
  호출 수를 세어 보고하고 상한은 60회다. 판정이 실패하면 자동 병합하지 않는다.
- 지표(평가용): 자동 병합한 쌍 수, 그중 `duplicate`가 아닌 쌍(**잘못 병합**), 자동으로 병합된 `duplicate` 비율, 사람 승인 후보 수, LLM 판정 정확도.
- **채택 기준**: 개발용·평가용 모두 **잘못 병합 0건**. 한 건이라도 있으면 자동 구간을 열지 않고 전부 사람 승인으로 둔다.
- 대표 제목: 병합 후보 묶음마다 LLM이 제안하고, 코드가 묶음의 카드 id만 인용했는지 확인한다. 어긋나면 폐기하고 기본 제목(가장 최근 카드의 결정 문장)을 쓴다.
  지표는 제안 수와 검증 통과 수다(상한 포함해 위 60회 안).

## 4. 호출 상한

- 임베딩: 400건 이하(카드 80장 + 질의 80건 정도). 이미 받은 벡터는 재사용한다.
- Claude: 60회 이하(판정 + 대표 제목). 넘으면 멈추고 보고한다. 무료 한도를 넘기지 않는다.

## 5. 한계 (결과와 함께 적는다)

- 합성 문장 80개, 쌍은 개발용·평가용 각 50개 안팎이라 비율은 참고 수준이다.
- 정답 라벨은 Claude가 정했다. `update`와 `duplicate`의 경계(숫자가 같은데 조건만 다른 경우)는 사람이 다르게 볼 수 있다.
- 이벤트 기록 카드(`incident`)는 시험하지 않고 병합·대체 대상에서도 제외한다(반복 이벤트마다 시각과 해결 기록이 근거라서).
