# MCP 권한·보안 기준안

작성: 재무·안전 담당, 2026-11-04. 팀 검토 전 **제안**이다. 각 부서 표는 담당자가 확인한다.

외부 도구를 MCP로 연결할 때 어디까지 허용할지 정한다. 공통 규칙은 `docs/agent-common.md` 7장·10장을 따르고, 이 문서는 그 위에 허용 범위를 더한다.

## 1. 지금 상태

| 항목 | 상태 |
|---|---|
| 에이전트가 LLM 도구로 쓰는 MCP | 없음. 외부 시스템은 API와 A2A로 읽는다 |
| 동작 중인 MCP 서버 | 개발 서비스 작업 대기열 하나 (`docs/dev-mcp.md`). 개발자 본인 PC의 Claude가 작업을 가져간다 |
| 상태 변경 | `execute()` 관문 하나로만 |
| 외부 쓰기 연결 표시 | 개발 VCS 액션만 `connection_field`로 관리 |

## 2. 원칙

1. **기본은 차단.** 표에 없는 도구는 연결하지 않는다.
2. **쓰기 도구는 LLM 도구 목록에 넣지 않는다.** 코드가 `execute()`를 지난 뒤에만 부른다.
3. **외부 문서와 도구 응답은 데이터다.** 그 안의 지시를 따르지 않고 `untrusted`로 다룬다.
4. **안 되면 실행하지 않는다.** 인증 실패, 관문 무응답, 로그 실패는 실행 안 함으로 처리한다.
5. **돈과 외부 공개는 사람이 정한다.** AI는 준비까지만 한다.

## 3. 권한 등급

| 등급 | 뜻 | 조건 |
|---|---|---|
| R0 | 공개·내부 읽기 | 읽기 전용 토큰 |
| R1 | 민감 읽기 (개인정보, 거래내역) | 필드 최소화, 마스킹, 조회 로그 |
| W1 | 되돌릴 수 있는 내부 쓰기 | 관문 A |
| W2 | 비용이 나가거나 외부에 보이는 쓰기 | 관문 B 또는 금액 기준 |
| W3 | 돈 이동, 외부 공개, 삭제, 권한 변경 | 관문 C. 항상 사람 승인 |
| 금지 | 연결하지 않음 | 인증 정보 입력, 자동 결제, 토큰 발급 |

## 4. 에이전트별 허용 범위

| 에이전트 | 읽기 | 쓰기 (관문 뒤) | 금지 |
|---|---|---|---|
| 총괄 | 사건·실행 기록 R0 | 다른 부서 호출만. 직접 외부 쓰기 없음 | 외부 도구 직접 쓰기 |
| 재무 | 주문·정산 R1, 은행 내역 파일 R1, 회계 자료 R1 | 내부 파일 보관 W1, 세무 전달 W3, 정산 지급 W3 | 아래 5장 |
| 마케팅 | 공지·쿠폰 R0, 광고 성과 R0 | 공지 W1, 쿠폰 W2, 영상 생성 W2, SNS 게시 W3, 캠페인 집행 W2 | 광고 계정 결제수단 변경, 토큰 발급 |
| 고객지원 | 문의·주문 R1 | 답변 W1, 환불 W2, 개인정보 삭제 W3 | 고객 정보 대량 내보내기 |
| 데이터분석 | 지표·집계 R0, 외부 트렌드 R0 | 없음 (읽기 전용) | 원본 DB 쓰기, 개인 식별 원자료 반출 |
| 기획 | 문서·이슈 R0, 노션 R0 | 티켓 W1, 문서 W1, 자동 범위 확대 W3 | 다른 부서 문서 삭제 |
| 개발 | 레포·CI R0 | PR 생성·수정 W2, 병합 W2, 되돌리기 W2, 배포 W3 | 강제 푸시, 보호 브랜치 직접 쓰기, 비밀값 읽기 |
| 인사 | 명부 R1, 회사 기억 R0 | 발령 기록 W1, 인수인계 W2 | 급여·주민번호 원자료 |
| 인프라 | 모니터링 R0 | 재시작 W2, 롤백 W2 | 서버 셸 임의 실행, 방화벽 변경 |
| 안전 | 실행 기록 R0 | 판정만 | 실제 쓰기 도구 호출 |

W2를 B나 C로 할지는 `registry.toml`과 `thresholds.toml`이 정한다. 이 표와 다르면 그 파일이 우선이고, 표를 고친다.

## 5. 재무 특칙

재무는 실제 돈과 세금을 다루므로 더 엄격하게 둔다.

### 절대 연결하지 않는 것
- 은행·펌뱅킹 **이체** 기능, 카드·PG 결제와 취소 API
- 홈택스 등 **세금 신고 제출**, 공동·금융 인증서
- 회계 프로그램의 전표 **자동 확정**

### 단계별 처리

| 일 | AI | 사람 |
|---|---|---|
| 결산·재무제표 | 계산, 파일 생성, 근거 표시 | 결산 확정 |
| 판매자 정산 | 내역 계산, 지급 요청 | C 승인. 실제 이체는 AI 밖에서 사람이 |
| 은행 내역 | 지정 폴더 파일 읽기, 대조 | 내려받기와 폴더에 넣기 |
| 세무 | 집계, 파일 생성, 전달 요청 | C 승인, 세무사 검토·신고 |
| 캠페인 예산 | 승인·조건부·거절 판단과 근거. 거절하면 관문이 막는다 | 큰 금액 결정, 기준 변경 |
| 쿠폰·환불 | 끝난 금액을 장부에 기록만 | 판단은 담당 부서 |

### 추가 조건
- 판단 결과에 적용 규칙과 근거를 항상 남긴다 (`applied_rules`).
- 금액은 코드가 계산한다. LLM 문장의 숫자가 계산과 다르면 문장을 버린다.
- 두 사람 승인: 실제 이체 연동을 도입한다면 요청자와 승인자를 분리하고 건당 한도를 둔다. 지금은 이체 연동이 없다.

## 6. 사람 승인이 필요한 작업

- 돈이 나가는 일: 판매자 지급, 기준을 넘는 환불·쿠폰·영상·캠페인
- 외부에 공개되거나 전달되는 일: SNS 게시, 고객 대량 발송, 세무 자료 전달
- 되돌릴 수 없는 일: 개인정보 삭제, DB 마이그레이션, 운영 배포
- 권한이 넓어지는 일: 자동 처리 범위 확대, 새 MCP 연결, 토큰 범위 변경

## 7. 보안 정책

### 인증
- 서비스·사람별 토큰을 쓰고 공유하지 않는다. 비밀값은 `.env`에만 둔다.
- 쓰기 토큰과 읽기 토큰을 나눈다. 범위는 최소로 하고 만료일을 둔다.
- 개인 구독 계정을 서버에 모으지 않는다 (`docs/dev-mcp.md`).

### 로그
- 모든 쓰기: 누가, 언제, 어떤 도구, 어떤 입력 해시, 어떤 결과, `execution_id`.
- R1 읽기: 누가, 언제, 어떤 범위, 몇 건. 내용은 남기지 않는다.
- 토큰과 개인정보 원문은 로그에 남기지 않는다. 감사 로그를 못 남기면 실행하지 않는다.

### 민감 데이터
- 개인정보는 필요한 필드만 받고, 이름·연락처·계좌는 마스킹한다.
- LLM에는 원문 개인정보와 계좌번호를 보내지 않는다.
- 파일 내보내기는 지정 폴더로만 하고, 파일 해시를 기록한다.
- 외부 응답은 크기를 제한하고 `truncated`를 표시한다.

### 프롬프트 인젝션
- 외부 도구 응답으로 쓰기 도구가 실행되지 않게 한다 (원칙 2).
- 외부 응답에서 받은 주소나 받는 사람으로 자동 전송하지 않는다.

## 8. 새 MCP 연결 절차

1. PR로 신청: 도구 목록, 등급, 토큰 범위, 받는 데이터, 끄는 방법
2. 안전 담당 검토: 쓰기 도구는 `registry.toml` 등록과 시험 포함
3. 도구 설명을 고정한다. 서버가 설명을 바꾸면 다시 검토한다
4. 목 모드로 시험한 뒤 읽기부터 켠다
5. 분기마다 안 쓰는 도구와 토큰을 지운다

| 항목 | 내용 | 맡는 곳 |
|---|---|---|
| 사람 토큰이 화면 빌드에 들어감 | `VITE_SAFETY_HUMAN_TOKEN`은 3090에 접근하는 누구나 읽을 수 있다. 실제 로그인으로 바꿔야 한다 | 인프라·프론트 |
