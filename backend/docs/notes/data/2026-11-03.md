## 2. 설계 결정

### 2-1. 계약은 추가만 (#381)

`TrendCandidate.youtube`가 필수라, YouTube 근거가 없는 인기 검색어 후보는 기존 모델의 타입을 바꾸지 않고 새 모델 `TrendingCandidate`와 출력 `trending_candidates`로 뺐다. 출처는 `origins`(youtube_tag·youtube_title·trending_search, 추천은 keyword_group 포함)로 새로 더했다.

### 2-2. 제목은 별도 표 (#382)

`snapshots` 표에 제목 칸을 더하면 돌고 있는 예전 수집기의 `INSERT … VALUES (11개)`가 깨진다. 그래서 `video_titles`(영상마다 한 줄) 표를 따로 두고, 예전 스냅샷 제목은 `youtube_collect --titles`로 채웠다(275개, 6단위).

### 2-3. 자동 제외 기준 (#382)

2026-11-02 스냅샷 전체(인기 영상 275개, 1일, 80%가 게임 카테고리)로 본 값:

| 카테고리 기준 | 영상 비율 | 자동 제외 (수동 목록 끈 상태) |
| --- | --- | --- |
| **3 (채택)** | **0.02** | 스트리머, 트위치 |
| 2 | 0.02 | 게임, 치지직, 로블록스, 스트리머, 아프리카tv, 피파, 트위치 |
| 3 | 0.01 | 스트리머, 트위치, vtuber, 버튜버, 강지, 개그, 버츄얼, 아이돌, 합방 |

카테고리 2개면 실제 소재(로블록스·피파), 비율 0.01이면 사람 이름(강지)까지 빠져 보수적인 값을 골랐다. 대신 `게임`은 자동으로 못 잡아 수동 목록을 남겼다(끄면 `게임`이 상위 5에 들어온다).

### 2-4. 자동 묶기는 로그 상관 (#383)

네이버 값은 요청마다 배수만 다르다(로그에서는 더하기). 그래서 따로 받은 두 이름의 판정 시계열을 로그로 바꿔 상관을 재면 추가 호출 없이 비교할 수 있다. 같은 영상에 함께 나온 적이 있어야 하고(우연히 모양이 비슷한 서로 다른 대상을 막으려고), 기준은 0.95로 보수적으로 뒀다.

### 2-5. 상품은 연결된 것만 문장에 (#384)

예전에는 회사 소개(`company_intro`)를 프롬프트에 넣어 관련 낮은 소재(t1 등)에도 "노트·젤펜" 같은 상품으로 억지로 잇는 문장이 나왔다(#370 한계). 이제 상품 이름은 연결된 실제 상품(데이터 블록)만 쓰게 하고, 연결 안 된 회사 상품 이름이 나오면 코드가 버린다. 회사 소개는 보조다.

### 2-6. 밈 형식은 목록 안에서만 (#385)

LLM 답이 목록 밖이면 기타, 근거(제목)가 없거나 LLM을 못 쓰면 unknown + 이유. 기타와 unknown을 섞지 않는다.

## 3. 알려진 한계

- **인기 검색어와 네이버의 하루 차이**: 피드는 오늘 뜨는 검색어, 네이버 판정은 어제까지라 오늘 처음 뜬 검색어는 평범·자료 없음일 수 있다 (#381)
- **회사와 무관한 뉴스 검색어**: 인기 검색어 후보는 뉴스성 검색어가 많다 (#381)
- **제목 구 조각**: 형태소 분석이 없어 `안 되는`·`진짜 말도` 같은 조각이 섞인다. 영상 수가 적어 상위 5에는 들지 않았다 (#382)
- **자동 제외 날짜 기준**: 스냅샷이 하루치라 아직 거르지 못한다 (#382)
- **수집기 재시작 필요**: 돌고 있는 YouTube 수집기는 예전 코드라 새 스냅샷에 제목이 쌓이지 않는다. 다시 켜기 전에는 `--titles`로 채운다 (#382)
- **자동 묶기 범위**: 상위 후보끼리만 보고, 영문 이름(lol·minecraft)은 못 찾는다 (#383)
- **임베딩 없음**: `DATA_EMBED_MODEL`/`EMBED_MODEL`이 없어 상품 유사도를 못 잰다. 오늘 추천 4개는 상품과 연결 0개 (#384)
- **평가셋 없음**: 후보 뽑기·자동 제외·자동 묶기·상품 연결·밈 형식 분류는 정확도를 재지 않았다. 기준값은 실데이터로 본 값이다 (#382 ~ #385)
