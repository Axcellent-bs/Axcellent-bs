# 판매자 정산을 재무에서 고객지원으로 옮김 (2026-11-12)

## 결정

팀장(태윤)이 정했다. **판매자 정산은 고객지원이 한다. 재무는 결과를 받아 보여 주기만 한다.**

- 재무 원칙: 다른 부서가 정하고 끝낸 일(쿠폰·환불)은 장부에 적기만 한다. 판매자 정산도 같은 원칙으로 둔다.
- 고객지원은 환불·클레임을 처리한다. 환불은 판매자 정산금에서 빠지므로, 정산을 같은 부서가 하면 처리 결과가 정산에 바로 이어진다.

## 흐름 (바뀐 뒤)

```
고객 문의·클레임 ─▶ 고객지원: 환불 판정 ─▶ execute(refund_request) ─▶ 판매 서버에 환불 기록
                                                                        │
판매 서버(주문·배송 완료·환불·쿠폰) ─────────────────────────────────────┤
                                                                        ▼
                         고객지원(claims): 판매자별 정산금 계산 · 지급 기한 점검
                                                                        │ 사람이 "지급 승인 요청" 누름
                                                                        ▼
                         execute(confirm_settlement) ─▶ 안전 장치 C 보류 ─▶ 사람이 승인
                                                                        │
                         재무: seller_settlement* 읽기 skill로 결과를 받아
                               화면 표시 · 미지급금 롤포워드 · 13주 현금 흐름 · 은행 출금 대조 · 마감 점검
```

| 일 | 전 | 후 |
| --- | --- | --- |
| 정산금 계산 (판매액 − 수수료 − 판매자 부담 쿠폰 − 환불) | 재무 | 고객지원 |
| 지급 승인 요청 (`confirm_settlement`) | 재무 | 고객지원 (레지스트리 owner `support`, 여전히 C) |
| 지급 승인 | 사람 (안전 장치 보류 큐) | 그대로 |
| 묶음 상태 기록 | 재무 `finance_state.json` | 고객지원 `support_settlement.json` |
| 지급 기한 점검 | 재무 | 고객지원 |
| 정산 화면 | 재무 탭 ③ (요청 버튼 있음) | 고객지원 화면 (요청 버튼), 재무 탭 ③은 읽기 전용 |
| 미지급금 롤포워드·현금 흐름·은행 출금 대조·마감 점검 | 재무 (직접 계산한 정산서) | 재무 (고객지원에서 받은 정산서·묶음) |

## 계산 기준 (바뀌지 않음)

- 판매액은 구매가 확정된(배송 완료) 주에 정산한다. 확정 전 주문은 확정되는 주로 넘긴다.
- 환불은 환불 시각과 구매 확정 시각 중 늦은 주에 뺀다. 끝내 확정되지 않은 주문의 환불은 빼지 않는다(#1003).
- 정산금 0원 이하면 보류(`negative_payout`), 확정 대기만 있으면 보류(`no_confirmed_orders`).
- 수수료율은 재무 매출 계산과 같아야 한다. 고객지원 `settlement_policy.toml`과 재무 `finance_policy.toml`의 `[commission]`을 같이 바꾼다.

## 옮기기

- 재무가 남긴 묶음 기록(예: 2026-W44 요청, W45 승인)은 고객지원이 처음 켜질 때 `SUPPORT_SETTLEMENT_IMPORT_FILE`(= `FINANCE_STATE_FILE`)에서 한 번 가져온다. 승인된 주를 잊고 다시 요청하지 않게 한다.
- 안전 장치에서 잃어버린 보류 건(재시작)은 고객지원이 읽을 때 `rejected`(`review_missing`)로 바꿔 다시 요청할 수 있다(#1002와 같은 처리).
- 서버(251)에 올릴 때: 고객지원(claims)·재무·안전 장치·대시보드 API·화면을 같이 다시 띄운다. nginx는 `POST /dashboard-api/api/dashboard/settlements/batch`(사람 쓰기)를 열어야 한다.
