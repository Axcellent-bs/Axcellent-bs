# 재무 AI 관리자 사용법

담당: 태윤 · 화면: 대시보드 → 상단 메뉴 **재무 AI** (`http://localhost:3001/finance`)
설계 원본: `docs/notes/finance/2026-10-23-finance-redesign.md` (재무 재설계, 2026-10-23)

## 한 줄 요약

재무 AI는 **캣북스의 재무팀**입니다. 결산, 매출·PG 대사, 판매자 정산, 팀 예산, 세무 지원을 맡습니다.
**쿠폰·환불은 끝난 금액을 장부에 기록만 합니다.** 건별 검사는 안전 장치의 코드 규칙(금액 계산, 기준표 한도)이 합니다.
보류된 환불은 고객지원 화면, 쿠폰은 마케팅 화면에서 사람이 결정합니다. 숫자는 모두 코드가 계산하고, AI는 설명 문장만 씁니다.

관리자가 할 일은 화면 맨 위 **"지금 사람이 할 일"** 목록을 위에서부터 처리하는 것입니다.

## 흐름

자동 수집 → 규칙으로 맞추고 분류 → **예외만 사람에게** → 결산·리포트

| 단계 | 누가 | 무엇을 |
| --- | --- | --- |
| 자료 모으기 | 재무 AI | 쇼핑몰 주문·결제·환불·쿠폰·판매자, 안전 장치 실행 기록 (데모는 가짜 장부) |
| 맞추고 나누기 | 재무 AI (코드 규칙) | 손익 계산, 결제 ↔ PG 정산 대사, 판매자 정산금, 팀 예산, 보류 추이 |
| 예외 처리 | **관리자** | 결산 확정, 대사 불일치 메모, 정산 묶음 지급 요청·승인, 팀 예산 확정 |

## 지금 사람이 할 일

| 할 일 | 어디서 | 어떻게 |
| --- | --- | --- |
| 판매자 정산 N곳 지급 승인 요청 대기 | ③ 판매자 정산 | 내역서를 보고 [정산 묶음 요청]. 보류 사유가 없는 판매자만 묶입니다. 요청은 안전 장치 **보류 큐(C)**로 가고, 지급 승인은 보류 큐에서 사람이 합니다 |
| 판매자 정산 지급 승인 대기 (안전 장치) | 안전 장치 보류 큐 | 판매자·기간·금액을 확인하고 [승인]/[거절]. 10분 안에 결정하지 않으면 자동 거절, 다시 요청할 수 있습니다 |
| 어제 결산 확정 대기 | ① 결산·리포트 | 손익 줄과 분개 미리보기를 보고 [결산 확정]. 이름과 시각이 남습니다 |
| 매출·PG 대사 불일치 N건 | ② 매출·PG 대사 | 건마다 원인을 확인하고 처리 메모를 남깁니다 (예: "PG사에 문의함"). 메모를 남긴 건은 할 일에서 빠집니다 |
| 팀 예산 확정 대기 | ⑤ 팀 예산 | 팀 인원과 금액을 보고 그 달 팀 예산을 확정합니다 |

결정 버튼(결산 확정, 대사 메모)은 사람 토큰이 있어야 눌립니다. 정산 묶음 요청은 토큰이 없어도 되지만, 지급 승인은 안전 장치에서 사람만 합니다.

## 다섯 개 영역

### ① 결산·리포트
- 일·월 손익: 총거래액(품목 판매가 합계), 판매 수수료 매출(도서 10%, 문구 8%), 쿠폰 비용(회사 부담), 환불, PG 수수료(3.1%), 영업 결과
- 영업 결과 = 수수료 매출 − 쿠폰 비용 − PG 수수료. 환불은 판매자 정산에서 빠지므로 영업 결과에 넣지 않습니다
- 자동 분개 미리보기(차변 합계 = 대변 합계), 쉬운 말 설명(AI가 못 쓰면 정해진 문장. 화면에 "템플릿"으로 표시)
- 쿠폰 비용은 쇼핑몰 쿠폰 기록(`GET /api/shop/coupons`)의 회사 부담분입니다. 지금 마케팅 `issue_coupon`은 쇼핑몰 쿠폰을 만들지 않아 장애 보상 쿠폰이 여기에 들어가지 않습니다. 보상 금액은 사건 장부에서 봅니다. 장애 손실 리포트(`loss_aggregation`)는 장애 대응 단계에서 빠졌습니다(2026-10-27, 아래 "장애 사건별 재무")

### ② 매출·PG 대사
결제 한 건씩 주문 금액 ↔ PG 정산을 맞춥니다.

| 상태 | 뜻 | 할 일 |
| --- | --- | --- |
| 일치 | 금액·수수료 모두 맞음 | 없음 |
| 정산 전 | 판매일 + 2일 지급 예정일이 아직 안 됨 | 없음 |
| 금액 다름 | PG 금액 ≠ 주문 금액 | PG사·주문 확인 후 메모 |
| PG에 없음 | 지급 예정일이 지났는데 PG 정산에 없음 | PG사 문의 후 메모 |
| 수수료 이상 | 수수료가 3.1% 계산과 1원 넘게 다름 | 계약 수수료 확인 후 메모 |

실제 PG가 없어 PG 정산은 **토스 정산 형식의 가짜 자료**이고, 데모용 불일치가 일부러 들어 있습니다.

### ③ 판매자 정산
- 정산금 = 판매액 − 판매 수수료 − 판매자 부담 쿠폰 − 환불. 주 단위(월~일), 기본은 지난주, 지급일은 기간 끝 + 6일
- 보류 사유(하나라도 있으면 묶음에서 빠짐): 구매 미확정(배송 완료 전) 주문, 정산금 0원 이하
- 묶음 상태: 없음 → 요청됨(안전 장치 보류 큐) → 승인됨/거절됨. 거절되면 다시 요청할 수 있습니다
- 안전 장치가 꺼져 있으면 요청이 되지 않고("안전 장치에 닿지 않음") 아무것도 기록되지 않습니다

### ⑤ 팀 예산
- 팀 예산 = 그달 1일 팀 인원(인사 AI) × 인당 월 단가. 지난달 대비 증감을 보여 주고 확정은 사람이 합니다

## 장애 사건별 재무 (시나리오 A, 2026-10-26)

> **2026-10-27 개정 (멘토 피드백):** 재무는 장부에 기록만 합니다. 총괄은 고객지원이 문의를 닫으면 재무를 불러 처리 결과를 장부에 기록하게 하고, 장애 중 나간 보상 쿠폰은 이벤트로 장부에 쌓여 평상시 결산에서 보입니다. 아래 ⑨⑩⑰ 화면·API는 **코드 정리 전까지 남아 있는 것**이고, 후속 코드 PR에서 지웁니다. 근거: `docs/scenarios/scn-a-server-incident.md`, 공통 구성안 후속 결정 22.

결제 장애처럼 사건(`ctx_inc_`)이 생기면 재무 AI는 끝난 금액을 장부로 보여 줍니다. 건별 승인·한도 사용률·사건 후 점검은 하지 않습니다(2026-11-02에 없앴습니다).

| 항목 | 재무 AI가 하는 일 | 화면·API |
| --- | --- | --- |
| 쿠폰 장부 | 보상 쿠폰을 사건별로 기록. **안전 장치 실행 기록**의 `issue_coupon` 중 끝난 것(`executed`)이 있으면 원본이고, 없는 사건만 `coupon.issued` 이벤트로 채움. 출처는 `ledger_source`(`events`·`safety_executions`·`seed`) | `GET /api/finance/incidents` |
| 환불 금액 | 사건 구간에 영향 고객에게 나간 환불 합계. 구간이나 영향 고객을 모르면 0원이 아니라 "확인할 수 없음" | 상세 `refunds`, `money_out_total` |
| 피해 숫자 | 데이터 AI 영향 분석 숫자 그대로 | 상세 `impact` |

- 데모(목 모드): 어제 05:00~05:30 결제 장애 `ctx_inc_scn_a_0001`(실패 6건·4명·95,000원, 보상 2,000원 × 4장)

## 바뀐 점 (2026-10-23)

- 쿠폰·환불은 안전 장치에서 **A(바로 실행)**입니다. 한도를 넘거나 적어 낸 금액이 계산과 다르면 지금처럼 사람 확인(C)
- 화면에서 "거래별 검증 목록", "AI가 결정한 건 목록", 네 갈래 처리 흐름은 빠졌습니다

## 화면의 다른 부분 (그대로)

| 영역 | 무엇을 보나 |
| --- | --- |
| 재무 AI 테스트 버튼 | 계산 규칙(결산·대사·정산·보류 추이)과 연결(안전 장치, 쇼핑몰, 데이터 AI)을 점검. 상태를 바꾸지 않음. 버튼을 누르지 않아도 서버가 10분마다 자동으로 돌려 마지막 결과를 보여 줌(자동/수동 표시, 다음 실행 시각). 주기는 `FINANCE_SELF_TEST_SECONDS`, 0이면 자동 실행 끔 |
| 장애로 생긴 손실 | 장애별 실패 주문, 피해 고객, 피해 금액, 보상, 총 손실 |
| 판매자 관리 | 판매자 입점 심사, 정산 멈춤 결과 |

## 자주 묻는 질문

**결정 버튼이 꺼져 있어요.**
데모(목 모드)에서는 ax-frontend `.env`에 `VITE_SAFETY_HUMAN_TOKEN=human:<이름>`을 넣고 대시보드를 다시 켭니다. 실제 운영은 사람용 토큰(`SAFETY_HUMAN_TOKENS` 또는 `FINANCE_HUMAN_TOKENS`)을 받습니다.

**"확인할 수 없음"이 보여요.**
원천 자료(쇼핑몰, 안전 장치)를 받지 못한 값입니다. 재무 AI는 추정값을 만들지 않습니다. 화면 아래 "받지 못한 자료"에 이름이 나옵니다.

**기록이 사라졌어요.**
결산 확정, 대사 메모, 정산 묶음 상태는 지금은 메모리에 있어 서버를 다시 켜면 비워집니다. 영구 저장은 다음 작업입니다.

**재무 서버를 혼자 띄워 보고 싶어요.**
ax-backend 루트에서 `FINANCE_MOCK=1 uv run uvicorn finance_agent.main:app --port 8105` (목 장부는 오늘 날짜 기준 최근 2주치). 정산 묶음을 안전 장치 보류 큐까지 보내 보려면 safety도 목 모드로 띄우고 `AX_SAFETY_URL=http://localhost:8001`을 줍니다. 안전 장치 주소가 없으면 목 모드에서는 바로 "승인됨"으로 보입니다(템플릿 목 동작).

## 없앤 기능 (2026-10-26)

- 캣북스 클레임 연동(환불·교환 신청 건별 확인): 건별 검사는 안전 장치의 일이라 재무에서 뺐습니다. `FINANCE_CATBOOKS_*` 설정도 없습니다.
- AI 기준 바꾸기 판단(`review_threshold_change`): 바꾸는 것은 사람이 기준표 PR로 합니다.
