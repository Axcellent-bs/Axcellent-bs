# 재무 AI 관리자 사용법

담당: 태윤 · 화면: AXcellent 왼쪽 메뉴 **재무 AI → 평상시 재무 업무** (`http://localhost:3090/finance/daily`)
설계 원본: `docs/notes/finance/2026-10-23-finance-redesign.md` (재무 재설계, 2026-10-23)

## 한 줄 요약

재무 AI는 **캣북스의 재무팀**입니다. 결산, 매출·PG 대사, 팀 예산, 세무 지원, 캠페인 재무, 현금 흐름을 맡습니다.
**판매자 정산(정산금 계산·지급 승인 요청·지급 기한 점검)은 고객지원이 합니다(2026-11-12).** 재무는 고객지원이 준 정산을 받아 보여 주고 회계(미지급금·현금 흐름·출금 대조·마감 점검)에만 씁니다. 지급 승인 요청은 고객지원 AI가 하고, 승인은 **고객지원 담당**이 고객지원 > 판매자 정산의 보류 큐에서 합니다. 재무는 승인하지 않습니다.
**쿠폰·환불은 끝난 금액을 장부에 기록만 합니다.** 건별 검사는 안전 장치의 코드 규칙(금액 계산, 기준표 한도)이 합니다.
보류된 환불은 고객지원 화면, 쿠폰은 마케팅 화면에서 사람이 결정합니다. 숫자는 모두 코드가 계산하고, AI는 설명 문장만 씁니다.

관리자가 할 일은 화면 맨 위 **"지금 사람이 할 일"** 목록을 위에서부터 처리하는 것입니다.

## 흐름

자동 수집 → 규칙으로 맞추고 분류 → **예외만 사람에게** → 결산·리포트

| 단계 | 누가 | 무엇을 |
| --- | --- | --- |
| 자료 모으기 | 재무 AI | 쇼핑몰 주문·결제·환불·쿠폰·판매자, 안전 장치 실행 기록 (데모는 가짜 장부) |
| 맞추고 나누기 | 재무 AI (코드 규칙) | 손익 계산, 결제 ↔ PG 정산 대사, 팀 예산, 보류 추이 |
| 예외 처리 | **관리자** | 결산 확정, 대사 불일치 메모 (팀 예산 확정은 인사 AI에서) |

## 지금 사람이 할 일

| 할 일 | 어디서 | 어떻게 |
| --- | --- | --- |
| 정산 기한 확인 필요 판매자 N곳 (알림) | ③ 판매자 정산 (읽기 전용) | 고객지원이 알려 준 기한을 넘기거나 넘길 판매자입니다. 재무에서 처리하지 않고 고객지원 화면에서 처리합니다 |
| 어제 결산 확정 대기 | ① 결산·리포트 | 손익 줄과 분개 미리보기를 보고 [결산 확정]. 이름과 시각이 남습니다 |
| 매출·PG 대사 불일치 N건 | ② 매출·PG 대사 | 건마다 원인을 확인하고 처리 메모를 남깁니다 (예: "PG사에 문의함"). 메모를 남긴 건은 할 일에서 빠집니다 |

결정 버튼(결산 확정, 대사 메모)은 사람 토큰이 있어야 눌립니다. 판매자 정산 묶음 요청은 고객지원 AI가 하고, 지급 승인은 고객지원 담당이 고객지원 화면의 안전 장치 보류 큐에서 합니다.

## 화면 탭 (①~⑦)

평상시 재무 업무 화면의 탭과 그 안의 섹션입니다(2026-11-12 정리, 11/13 ⑧ 요청·기록 탭을 없애고 나눠 옮김). 탭 주소는 `#closing` 같은 해시이고, 섹션 주소(`#cashflow`, `#deadlines` 등)로 열면 그 섹션이 있는 탭이 열립니다.

| 탭 (주소) | 섹션 |
| --- | --- |
| ① 결산·리포트 (`#closing`) | 월 마감 체크리스트, 일·주·월 결산(손익 요약·분개 미리보기·결산 확정·조정), 월간 변동 분석, 재무제표(장부 밖 손익 입력 포함), 고객지원 비용 기록 |
| ② 매출·PG 대사 (`#reconciliation`) | PG 대사(PG 정산 파일 올리기), 은행 입금 대조(은행 거래내역 파일 올리기), 은행 거래내역 읽은 기록(이 내역 빼기), 은행 출금 대조(항목별 출금·설명 없는 출금) |
| ③ 판매자 정산 (`#settlements`, 읽기 전용) | 판매자 정산 표, 판매 대금 지급 기한, 판매자 미지급금 롤포워드, 판매자 정산 이체(은행 출금 대조 중 판매자 몫) |
| ④ 팀 예산 (`#policy`) | 팀 예산 |
| ⑤ 세무 지원 (`#tax`) | 부가세 신고 보조 집계, 판매자별 판매 명세, 법인세 참고 추정, 자동으로 만든 파일(세무사 전달용), 회계 기준 확인 목록 |
| ⑥ 캠페인 재무 (`#campaigns`) | 캠페인 손익, 예산 의견, 실패 교훈, 재무 인사이트, 총괄에 낸 의견 |
| ⑦ 자금·현금 흐름 (`#cash`) | 13주 현금 흐름(통장 기초 잔액·예상 잔액) |

탭 밖(늘 보임): 재무 AI 테스트, **기획에 개선 요청**(기획이 되물은 질문·보낼 요청·보낸 요청), **총괄이 재무에 맡긴 일**(최근 7일 실패는 지금 할 일에도), 지금 사람이 할 일, 오늘의 재무 숫자, 안전 장치 보류 큐(화면 맨 아래. 재무 장애 이슈 화면에서도 보이고, 할 일의 "보류 큐에서 결정하기"가 이리로 내려옵니다).


### ① 결산·리포트
- 일·월 손익: 총거래액(품목 판매가 합계), 판매 수수료 매출(도서 10%, 문구 8%), 쿠폰 비용(회사 부담), 환불, PG 수수료(3.1%), 영업 결과
- 영업 결과 = 수수료 매출 − 쿠폰 비용 − PG 수수료. 환불은 판매자 정산에서 빠지므로 영업 결과에 넣지 않습니다
- 자동 분개 미리보기(차변 합계 = 대변 합계), 쉬운 말 설명(AI가 못 쓰면 정해진 문장. 화면에 "템플릿"으로 표시)
- 쿠폰 비용은 쇼핑몰 쿠폰 기록(`GET /api/shop/coupons`)의 회사 부담분입니다. 마케팅 `issue_coupon`이 쇼핑몰 쿠폰을 만들기 때문에 장애 보상 쿠폰도 발급한 기간의 쿠폰 비용에 들어갑니다. 사건별 보상 합계는 사건 장부(`/api/finance/incidents`)에서 봅니다. 장애 손실 리포트(`loss_aggregation`)는 장애 대응 단계에서 빠졌습니다(2026-10-27, 아래 "장애 사건별 재무")

### ② 매출·PG 대사
결제 한 건씩 주문 금액 ↔ PG 정산을 맞춥니다.

| 상태 | 뜻 | 할 일 |
| --- | --- | --- |
| 일치 | 금액·수수료 모두 맞음 | 없음 |
| 정산 전 | 판매일 + 2일 지급 예정일이 아직 안 됨 | 없음 |
| 금액 다름 | PG 금액 ≠ 주문 금액 | PG사·주문 확인 후 메모 |
| PG에 없음 | 지급 예정일이 지났는데 PG 정산에 없음 | PG사 문의 후 메모 |
| 수수료 이상 | 수수료가 3.1% 계산과 1원 넘게 다름 | 계약 수수료 확인 후 메모 |

실제 PG 연동(API)은 아직 없습니다. PG 자료는 두 가지입니다.

- **올린 PG 정산 파일**: PG 관리자 화면에서 받은 정산 내역 CSV를 대사 화면의 "PG 정산 파일 올리기"로 올리거나, 폴더 `FINANCE_PG_INBOX`(`run_all.sh` 기본 `backend/.data/finance_pg_inbox`)에 넣습니다. 폴더는 은행 폴더와 같은 주기로 읽고, 읽은 파일은 `processed/`·`failed/`로 옮깁니다. 파일이 덮는 판매일 기간의 결제는 이 파일과 맞추고, 파일에 없는 결제는 "PG에 없음"입니다.
  - 받는 칸: 결제번호(`payment_id`·결제키), 주문번호, 결제금액, 수수료, 판매일(결제일), 지급일(정산일, 없으면 판매일 + 2일)
  - 같은 결제 번호를 다시 올리면 새 줄로 바꿉니다(PG가 정정한 파일). 올린 사람·파일·기간은 기록에 남습니다
  - "올린 PG 자료 빼기"(`POST /api/finance/pg/clear`, 이유 필수)로 모두 뺄 수 있습니다. 뺀 기록도 남습니다
- **결제 기록으로 만든 모의 자료**(토스 정산 형식): 파일이 없는 날입니다. 결제 기록 그대로라 불일치가 나오지 않습니다(데이터를 지어내지 않는다)

은행 거래내역도 잘못(시험으로) 올린 기록 하나를 뺄 수 있습니다. ② 매출·PG 대사 > 은행 거래내역 읽은 기록의 "이 내역 빼기"(`POST /api/finance/bank/imports/{import_id}/remove`, 사람 토큰, 이유 필수)가 그 기록으로 더한 줄과 출금 대조 기간만 뺍니다. 원래 기록에는 뺀 사람·시각·이유가 붙고, 빼기 기록도 따로 남습니다. id가 생기기 전(2026-11-12 전)에 읽은 기록은 그런 기록이 하나뿐일 때만 뺄 수 있습니다.

화면 위에 "PG 자료: …" 줄로 이번 대사가 무엇과 맞췄는지 보여 줍니다. 자기 테스트·정확도 평가는 올린 파일을 섞지 않습니다.

**대사 예외 시연** (운영자 명령, 쇼핑몰 장애 넣기와 같은 방식)

```bash
bash backend/scripts/pg_demo_file.sh          # 최근 정산 기간의 PG 정산 파일을 만들어 올린다
bash backend/scripts/pg_demo_file.sh clear    # 시연 끝: 올린 PG 자료 빼기
```

- 쇼핑몰의 실제 결제로 판매일 오늘−6일 ~ 오늘−2일 정산 파일을 만들고, 4건에 PG 쪽 사건을 넣습니다: 부분 취소가 PG에만 반영(−2,000원), 정산 보류(파일에 없음), 계약과 다른 수수료 3.5%, PG 금액 +1,000원
- 무엇을 바꿨는지 터미널에 모두 출력하고, 파일 이름·첫 줄에 "시연 시나리오"를 적습니다. 화면에서 올리는 것과 같은 길로 올라갑니다
- 시연이 끝나면 꼭 `clear`로 뺍니다. 빼지 않으면 그 기간 대사에 시연 예외가 남습니다

### ③ 판매자 정산 (고객지원이 계산, 재무는 보기만)
- 정산금 계산·보류 사유·묶음 지급 요청·지급 기한 점검은 고객지원이 합니다. 재무 화면은 고객지원이 준 내역서와 묶음 상태를 그대로 보여 줍니다(읽기 전용)
- 재무는 받은 정산을 회계에만 씁니다: 판매자 미지급금 롤포워드(승인된 묶음 = 지급), 판매자 정산 이체(은행 출금 대조), 13주 현금 흐름(⑦, 지급 예정), 월 마감 체크리스트(①, 지급일이 지난 주의 묶음 승인)
- 고객지원에 닿지 않으면 정산 화면은 "고객지원에서 받지 못함"(`support_unavailable`)이고, 정산을 쓰는 숫자는 0이 아니라 "확인할 수 없음"으로 보입니다

### ④ 팀 예산
- 팀 예산 = 그달 1일 팀 인원(인사 AI) × 인당 월 단가. 지난달 대비 증감을 보여 줍니다
- 확정은 인사 AI에서 사람이 합니다(11/13). 인사가 확정하면 재무 `record_team_budget`으로 기록만 남고, 재무 화면에는 확정 버튼이 없습니다

### ⑤ 세무 지원
- 부가세 신고 보조 집계·판매자별 판매 명세·법인세 참고 추정은 신고할 때 쓸 숫자이고, 신고·제출은 사람이 합니다
- 자동으로 만든 파일: 지난달 손익계산서와 분기 자료 묶음. 내려받아 세무사에게 전달합니다
- 회계 기준 확인 목록(`GET /api/finance/rules`): 재무 AI가 계산에 쓰는 결산·세무 기준과 세무사·회계사 확인 여부, 먼저 물을 질문

### ⑥ 캠페인 재무
- 캠페인 손익과 예산 의견(재무), 실패 교훈, 재무 인사이트, 총괄에 낸 의견

### ⑦ 자금·현금 흐름
- 13주 현금 흐름: PG에서 들어올 돈과 판매자에게 나갈 돈. 은행 거래내역(②에서 올림)이 있으면 통장 잔액에서 시작해 예상 잔액과 현금 부족 예상 주를 보여 줍니다

### 기획에 개선 요청 (탭 밖, 총괄이 재무에 맡긴 일 바로 위)
- 재무 업무에서 고칠 점과 근거를 기획에 보냅니다. 탭 밖에 늘 펼쳐 둡니다
- ② 대사 예외, ① 기한 지난 마감 항목, 재무 AI 테스트 실패 옆 `이걸로 개선 요청`은 제목·근거를 미리 채워 엽니다
- 기획이 되물었는데 재무 AI가 보낸 기록으로 답하지 못한 질문은 패널 맨 위와 "지금 사람이 할 일"에 올라옵니다. 답하면 기획서 근거로 남습니다
- 잘못 보낸 요청은 줄 오른쪽 `요청 빼기` → `기획에서도 지우기`로 뺍니다. 기획 목록에서도 지워집니다
  - 이미 개발로 넘어간 요청은 기획이 지우지 않습니다. 기획 화면에서 사람이 중단·기각합니다
- 옛 주소 `#requests`·`#planning-requests`는 평상시 업무와 이 패널로 엽니다

### 고객지원 비용 기록 (① 결산·리포트)
- 고객지원이 문의를 닫을 때 끝난 환불·쿠폰을 배송비와 함께 장부에 적은 기록(읽기 전용)

### 총괄이 재무에 맡긴 일 (탭 밖, 재무 AI 테스트 아래)
- 총괄이 재무에 맡긴 일과 그 결과. 최근 7일에 실패·거절이 있으면 "지금 사람이 할 일"에도 올라옵니다

## 장애 사건별 재무 (시나리오 A, 2026-10-26)

> **2026-10-27 개정 (멘토 피드백):** 재무는 장부에 기록만 합니다. 총괄은 고객지원이 문의를 닫으면 재무를 불러 처리 결과를 장부에 기록하게 하고, 장애 중 나간 보상 쿠폰은 이벤트로 장부에 쌓여 평상시 결산에서 보입니다. 손실 집계(`loss_aggregation`, `/api/finance/loss-reports`)는 지웠습니다. 근거: `docs/scenarios/scn-a-server-incident.md`, 공통 구성안 후속 결정 22.

## 자주 묻는 질문

**결정 버튼이 꺼져 있어요.**
로컬은 `bash backend/scripts/run_web.sh`로 화면을 켜면 사람 토큰(`VITE_SAFETY_HUMAN_TOKEN`)이 들어갑니다. 서버는 화면 env에 같은 값을 넣고 다시 켭니다. 실제 운영은 사람용 토큰(`SAFETY_HUMAN_TOKENS` 또는 `FINANCE_HUMAN_TOKENS`)을 받습니다.

**"확인할 수 없음"이 보여요.**
원천 자료(쇼핑몰, 안전 장치)를 받지 못한 값입니다. 재무 AI는 추정값을 만들지 않습니다. 화면 아래 "받지 못한 자료"에 이름이 나옵니다.

**기록이 사라졌어요.**
결산 확정, 대사 메모, 이벤트로 쌓은 쿠폰·환불 장부, 올린 PG 자료는 `FINANCE_STATE_FILE`(`run_all.sh` 기본 `backend/.data/finance_state.json`)에 남아 다시 켜도 이어집니다. 이 설정 없이 띄우면 메모리에만 있어 다시 켤 때 비워집니다.

**재무 서버를 혼자 띄워 보고 싶어요.**
`backend/`에서 `FINANCE_MOCK=1 uv run uvicorn finance_agent.main:app --port 8105` (목 장부는 오늘 날짜 기준 최근 2주치). 판매자 정산은 고객지원 서버가 있어야 보입니다.

## 없앤 기능 (2026-10-26)

- 캣북스 클레임 연동(환불·교환 신청 건별 확인): 건별 검사는 안전 장치의 일이라 재무에서 뺐습니다. `FINANCE_CATBOOKS_*` 설정도 없습니다.
- AI 기준 바꾸기 판단(`review_threshold_change`): 바꾸는 것은 사람이 기준표 PR로 합니다.
