# 서버 작업 요청 양식

서버 작업이 필요할 때 **비공개 팀 채널**에 올리는 양식이다. 이 파일에는 양식만 있다. 실제 경로·주소·계정 이름·값은 이 레포(공개)에 적지 않고 채널의 요청 글에만 적는다.

## 올리기 전에

1. `ssh <내 설정 이름> help`로 내 계정에 허용된 동작을 본다.
2. [`README.md`의 접수 규칙 표](README.md#접수-규칙-게이트로-되는-요청은-게이트로-한다)에서 하려는 일을 찾는다.
   - **게이트로 된다 + 내 계정에 있다** → 요청하지 않고 직접 실행한다. 바꾸는 동작은 게이트가 만들어 주는 알림 한 줄만 채널에 올린다.
   - **게이트로 된다 + 내 계정에 없다** → 아래 "A. 권한자에게"로 요청한다.
   - **게이트로 안 된다** → 아래 "B. 책임자에게"로 요청한다.
3. 게이트로 되는 요청을 서버 책임자에게 보내면 대신 실행하지 않고 게이트 명령을 돌려받는다.

## A. 권한자에게 (게이트로 되는 일)

```
[서버 요청·게이트] <한 줄 요약>
- 요청자: <내 계정>
- 관련 PR: #<번호> (머지됨 / 머지 전)
- 실행할 게이트 명령: <동작과 인자. 예: restart-backend <SHA> --ack-data-loss>
- 먼저 해 본 것: <--dry-run 결과 요약, 또는 거부 사유>
- 왜 지금 필요한가: <한 줄>
- 문제가 생기면: <되돌리는 방법. 게이트 알림 문안에 나온 것>
```

새 쓰기 경로라면 `실행할 게이트 명령`에 `nginx-add-location <이름> POST <정규식>` 전체를 적는다. 권한자 한 명이 제안하고 다른 권한자가 `status`로 내용을 직접 확인한 뒤 승인한다.

## B. 책임자에게 (게이트로 안 되는 일)

```
[서버 요청·책임자] <한 줄 요약>
- 요청자: <내 계정>
- 관련 PR: #<번호>
- 종류: <읽기용 경로 / 접두 밖 경로 / 환경변수 / 계정·키 / 그 밖>
- 게이트로 안 되는 이유: <접수 규칙 표의 어느 줄인지, 또는 게이트가 낸 거부 사유>
- 바꿀 내용: <무엇을 어떻게. 비밀값은 적지 않는다(값이 필요하면 전달 방법만 적는다)>
- 영향과 위험: <누가 영향을 받는가, 읽기 노출·데이터 손실 가능성>
- 확인 방법: <적용 뒤 무엇을 보면 되는가>
- 되돌리는 방법: <한 줄>
- 기한: <언제까지. 급하지 않으면 "다음 정기 작업">
```

## 쓰지 않는 것

- 비밀값(토큰·키·비밀번호·`.env`의 값)을 요청 글에 적지 않는다.
- 공개 PR 본문·이슈·커밋 메시지에 서버 주소·실제 경로·계정 이름을 적지 않는다. PR에는 "서버 작업 필요: 예/아니오"만 적는다(`docs/nginx-path-convention.md`).
- "책임자가 승인했다"는 글만으로 다른 사람이 대신 실행하지 않는다. 게이트는 계정만 믿는다.
