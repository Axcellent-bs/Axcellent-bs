## 요약

서버 위임 게이트(ax-gate) 개선 3개 중 2번. 가장 잦은 서버 요청인 "같은 쓰기 경로를 두 설정 파일에 같이 열기"와 "타임아웃·본문 크기가 다른 경로"를 게이트로 할 수 있게 한다. 둘 다 정책에 적어야 켜지고, 정책에 없으면 동작은 지금과 같다.

- **nginx 다중 대상** (정책 `[nginx_targets] 이름 = "경로"`, 선택)
  - 기본 대상은 지금처럼 `[paths] nginx_conf`. 추가 대상을 적으면 제안·승인·복원이 **대상 전부**에 적용된다. 요청하는 사람은 대상을 고르지 못한다.
  - 승인 순서: 전 대상 사전 검증(걸리면 백업 폴더도 안 만든다) → 전부 백업 → 전부 교체 → `nginx -t` 1회 → reload. 교체·`nginx -t`·reload 어디서 실패하든 이미 바꾼 파일까지 전부 되돌린다.
  - 백업: 기본 대상은 기존 위치 그대로, 추가 대상은 `<백업폴더>/targets/<이름>/`.
  - `nginx-restore`도 같은 원자성. 추가 대상의 사본이 없는 옛 백업은 그 대상을 그대로 두고 알린다.
  - 대상별 블록 줄(`[nginx_target_block_lines]`, 선택): 그 대상의 기존 location 모양이 다를 때만.
- **블록 프로필** (정책 `[location_profiles] 이름 = [지시어…]`, 선택)
  - `nginx-add-location <이름> POST <정규식> [프로필]`. 요청하는 사람은 이름만 고른다.
  - 검증기에 지시어 허용 목록을 고정했다: `proxy_read_timeout` `proxy_send_timeout` `proxy_connect_timeout` `send_timeout` `client_body_timeout`(1~3600초), `client_max_body_size`(1k~1024m, 0 불가). 줄 꼴은 `<지시어> <숫자><단위>;` 하나. `proxy_pass`·`include`·`rewrite`·`add_header` 등은 정책에 적어도 거부한다.
  - 프로필 줄은 정책 블록 줄 뒤에 덧붙을 뿐이다. 메서드 제한·`proxy_pass`·include는 못 바꾼다.
  - 프로필 이름을 제안 파일과 확인값에 묶었다. 프로필이 없으면 확인값·제안 파일·블록 글이 지금과 글자까지 같다(테스트로 고정).
- **GET·HEAD는 넣지 않았다.** 앱의 GET이 토큰을 요구하지 않아 nginx에서 열면 읽기 노출이 된다. 재헌 결정 전이다.
- reload 실패 때도 되돌리게 했다(지금은 reload가 실패하면 바뀐 파일이 그대로 남는다).

## 테스트

신규 테스트가 보는 것
- 원자성: `nginx -t` 실패, 둘째 대상 교체 도중 실패(가짜 `cp`가 그 파일만 한 번 실패), reload 실패 → 세 경우 모두 두 파일이 원래대로, 제안은 승인 대기로 남음.
- 사전 검증: 둘째 대상에 삽입 표시 줄이 없거나 같은 정규식이 이미 있으면 제안·승인이 아무것도 바꾸지 않고 멈춤(백업 폴더도 없음).
- `nginx -t`·reload가 한 번씩인지, 백업 위치, 복원이 두 파일을 같이 되돌리는지, 백업 사본 변조 시 체크섬에서 멈추는지.
- 대상을 고를 수 없는지(넷째 인자는 프로필 이름으로만 해석), 잘못된 대상 정책은 nginx 동작만 설정 오류로 멈추고 status는 되는지.
- 프로필: 허용 목록 밖 지시어·한도 밖 값·한 줄에 두 지시어·블록 닫기 시도 거부, 없는 프로필, 제안 뒤 프로필이 빠지거나 위험하게 바뀐 경우 승인 거부, 제안 파일의 프로필 변조 → 확인값 불일치.
- 회귀: 프로필·추가 대상이 없으면 확인값이 예전 공식과 같고 백업 폴더에 `targets/`가 없음.
- PR1과 맞물림: `help`와 `help nginx-add-location`에 `[프로필]`이 나오는지, 인자 개수 오류의 형식 줄에 나오는지, 프로필 인자가 있어도 플래그 위치가 자유로운지.

실제 nginx에서는 돌려 보지 않았다.

## 위험

- **root로 도는 코드가 바뀐다.** nginx 백업·교체·복원 경로를 새 함수로 옮겼다. 단일 대상 동작은 기존 테스트 전부가 그대로 통과하는 것으로 확인했다.
- 되돌리는 복사 자체가 실패하면(디스크 등) 파일이 어긋난 채 남는다. 게이트는 경고를 출력하고 실패로 끝낸다.
- 프로필 지시어가 include된 스니펫에 이미 있으면 nginx가 중복으로 거부할 수 있다. 그 경우 `nginx -t`에서 걸려 전부 되돌린다. 설치 때 시험 경로로 한 번 확인하게 INSTALL에 적었다.
- 프로필 내용은 승인 시점의 정책에서 읽는다. 확인값에는 프로필 **이름**만 묶인다. 정책은 root만 바꾸므로 이름만 묶었다.
- 운영 사본(`ops_copy_file`)과 status의 사본 비교는 기본 대상만 본다.
- sudoers·권한표·셀프 승인 범위는 그대로다. 새 동작은 없다(기존 동작의 인자 하나와 정책 구역 셋).
