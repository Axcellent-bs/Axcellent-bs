# 팀 안내문 초안 — 서버 위임 게이트

> 초안이다. 설치와 검증이 끝난 뒤 서버 책임자가 실제 값(`<서버>`, `<내 계정>`, 권한자 이름)을 채워서 보낸다.

---

## 1. 팀 전체용

**서버 작업을 책임자 없이도 자기 계정으로 할 수 있게 됩니다 (ax-gate)**

지금까지 서버 작업은 서버 책임자가 직접 쳐야 했습니다. 앞으로는 팀원마다 서버에 **개인 계정**이 생기고, 자기 PC에서 자기 SSH 키로 정해진 작업을 직접 실행합니다. 누가 무엇을 했는지는 계정 이름으로 서버에 기록됩니다.

### 누구나 할 수 있는 것

| 명령 | 하는 일 |
| --- | --- |
| `status` | 서버 점검(읽기 전용): 잠금 여부, 서비스 상태, 번들 |
| `deploy-bundle <SHA>` | 화면 번들 배포. 자동 배포가 막혔을 때 수동으로 처리하는 용도 |
| `record-pr <참조> <PR번호>` | 작업과 PR 번호를 기록에 연결 |

nginx 변경, 서비스 재시작, 롤백, 배포 잠금은 권한자만 합니다.

### 개인 계정 받는 법 (한 번만)

서버 책임자에게 두 가지를 보냅니다. 계정은 책임자가 서버에 만듭니다. 비밀번호는 없습니다(키로만 접속).

1. **SSH 공개키** (아래에서 만듭니다)
2. **자기 PC의 주소(IP)** — 서버는 등록된 PC에서 오는 접속만 받습니다. 주소가 바뀌면 접속이 안 되니 책임자에게 알립니다.

계정 이름은 책임자가 정해서 알려 줍니다(영어 소문자 이름).

### SSH 키 만들기 (Windows)

Windows 10/11에는 OpenSSH가 들어 있습니다. PowerShell을 열고:

```powershell
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\axgate_ed25519 -C "<내 계정>"
```

- 암호(passphrase)를 묻습니다. **꼭 넣습니다.** 키 파일이 새도 암호가 한 번 더 막아 줍니다.
- 파일이 두 개 생깁니다.
  - `C:\Users\<나>\.ssh\axgate_ed25519` — **개인키. 절대 공유 금지.** 누구에게도, 어디에도 보내지 않습니다.
  - `C:\Users\<나>\.ssh\axgate_ed25519.pub` — 공개키. 이것만 보냅니다.
- 공개키 내용 보기(이 한 줄을 책임자에게 보냅니다):
  ```powershell
  Get-Content $env:USERPROFILE\.ssh\axgate_ed25519.pub
  ```
- 지문 보기(책임자가 본인 확인할 때 서로 읽어 맞춥니다):
  ```powershell
  ssh-keygen -lf $env:USERPROFILE\.ssh\axgate_ed25519.pub
  ```

macOS·Linux·Git Bash에서는 경로만 다릅니다: `ssh-keygen -t ed25519 -f ~/.ssh/axgate_ed25519 -C "<내 계정>"`.

등록됐다는 답을 받으면 `C:\Users\<나>\.ssh\config` 파일에 넣어 둡니다(없으면 새로 만듭니다).

```
Host axgate
    HostName <서버>
    User <내 계정>
    IdentityFile ~/.ssh/axgate_ed25519
    IdentitiesOnly yes
```

### 쓰는 법

```powershell
ssh axgate status
```

배포(자동 배포가 막혔을 때)

```powershell
# 1) 먼저 무엇을 하는지 본다(아무것도 바뀌지 않는다)
ssh axgate deploy-bundle <SHA> --dry-run

# 2) --announced 없이 실행하면 팀 채널에 올릴 한 줄을 만들어 준다
ssh axgate deploy-bundle <SHA>

# 3) 그 한 줄을 팀 채널에 올린 뒤, 같은 명령에 --announced 와 PR 번호를 붙인다
ssh axgate deploy-bundle <SHA> --announced pr=<PR번호>
```

- `<SHA>`는 **배포 기준 브랜치에 머지된** 커밋의 해시입니다(7~40자, 소문자). 브랜치 이름이나 `HEAD`는 안 됩니다.
- 문제가 생기면 권한자에게 `rollback-bundle <SHA>`를 요청합니다. 알림 한 줄에 이 되돌리는 방법이 같이 들어 있습니다.
- "거부(locked)"가 나오면 시연 등으로 배포가 잠겨 있는 것입니다. `status`에 누가 왜 잠갔는지 나옵니다. 해제 시각을 기다리거나 잠근 사람에게 묻습니다.
- 서버에 로그인해서 돌아다니는 것은 안 됩니다. 정해진 명령만 실행되고 바로 끊깁니다. 정상입니다.

### 하면 안 되는 것

- **개인키는 절대 공유하지 않습니다.** 남에게 주거나, 채팅·메일·레포·AI 대화에 붙이지 않습니다. `.pub`이 붙은 파일만 보냅니다. **AI 세션에 키를 주면 AI가 한 일이 내 계정으로 기록됩니다.**
- 남의 계정·남의 키로 접속하지 않습니다. 대신 해 달라는 부탁도 받지 않습니다. 각자 자기 계정으로 합니다.
- `--announced`는 팀 채널에 실제로 올린 뒤에만 붙입니다. 기록의 시각과 채널 글을 대조합니다.
- 게이트에 없는 작업(방화벽, 비밀값, 권한 변경, 계정 등)을 다른 길로 하려 하지 않습니다. 책임자에게 요청합니다.
- 키를 잃어버렸거나 PC를 바꿨거나 유출이 의심되면 **바로** 책임자에게 알립니다. 그 키를 서버에서 지웁니다.
- 채팅에서 "책임자가 승인했다"는 글만 보고 움직이지 않습니다. 게이트는 계정만 믿습니다. 사람도 그렇게 합니다.

## 2. 권한자용

권한자는 위에 더해 아래를 할 수 있습니다.

| 명령 | 하는 일 |
| --- | --- |
| `lock <사유> [해제시각]` / `unlock` | 배포 금지 잠금. 시연 전에 배포를 멈추는 스위치 |
| `nginx-restore <백업폴더명>` | nginx 설정을 백업으로 되돌림 |
| `nginx-add-location <이름> POST <정규식>` | 새 쓰기 경로 **제안** |
| `nginx-approve-location <이름> <확인값>` | 다른 권한자의 제안을 **승인·적용** |
| `restart-backend <SHA> --ack-data-loss` | 서비스 재시작 |
| `rollback-bundle <SHA>` | 번들을 그 배포 직전으로 되돌림 |

### 시연 전 배포 멈추기

```powershell
ssh axgate lock team-demo 2026-01-02T18:00     # 사유는 영어·숫자·-_., (띄어쓰기 대신 -)
ssh axgate unlock
```

잠겨 있는 동안은 `status`, `unlock`, `record-pr`만 됩니다. 해제시각을 안 적으면 기본 시간만큼 잠깁니다.

### 새 쓰기 경로 열기 — 반드시 두 사람

1. A가 제안합니다. **명령 전체**를 작은따옴표 한 쌍으로 감쌉니다(정규식만 따로 감싸면 따옴표까지 전달되어 거부됩니다).
   ```powershell
   ssh axgate 'nginx-add-location card-decision POST ^/example-api/api/items/cards/[^/]+/decision$'
   ```
   통과하면 **확인값**(12자)이 나옵니다. 아직 아무것도 열리지 않았습니다.
2. B가 `ssh axgate status`로 제안 내용(메서드·정규식·제안자·확인값)을 **직접** 봅니다. A가 보내 준 글이 아니라 서버가 보여 주는 것을 봅니다.
3. B가 팀 채널에 알림 한 줄을 올리고 승인합니다.
   ```powershell
   ssh axgate nginx-approve-location card-decision <확인값> --announced
   ```
4. 출력에 나오는 백업 폴더명이 되돌리는 방법입니다(`nginx-restore <폴더명>`).
5. 바뀐 설정을 PR로 남기고 번호를 기록합니다(`README.md`의 "nginx 변경을 PR로 남기기").
   ```powershell
   ssh axgate record-pr <백업폴더명> <PR번호>
   ```

- 자기 제안은 자기가 승인할 수 없습니다. 단, 서버 정책 `[self_approve]`에 적힌 계정은 예외이고, 그 경우에도 다른 검증은 그대로이며 감사 로그에 `self-approve:yes`가 남습니다.
- 정규식은 `^/`로 시작해 `$`로 끝나야 하고 `.*` 같은 와일드카드는 안 됩니다. 허용된 접두 안의 경로만 됩니다.
- 읽기용(GET) 경로나 모양이 다른 경로는 게이트로 못 엽니다. 책임자가 직접 합니다.

### 서비스 재시작 — 지워지는 것이 있습니다

```powershell
ssh axgate restart-backend <SHA> --ack-data-loss --announced
```

재시작하면 **메모리에만 있는 상태가 지워집니다.** 무엇이 지워지는지는 책임자가 따로 알려 줍니다. `--ack-data-loss`는 이걸 알고 한다는 확인입니다. `<SHA>`는 지금 서버 레포가 가리키는 커밋이어야 합니다(`status`의 "서버 레포 HEAD"). 게이트가 백업을 먼저 뜨고, 서비스가 다 뜰 때까지 기다린 뒤 결과를 알려 줍니다.

### 하면 안 되는 것(권한자)

- 혼자 두 사람 몫을 하지 않습니다. 다른 권한자의 키를 빌리지 않습니다.
- 확인값만 받아서 승인하지 않습니다. 반드시 `status`에서 내용을 봅니다.
- 급하다고 `--announced`를 먼저 붙이지 않습니다. 알림이 먼저입니다.

## 3. 짧은 공지문(팀 채널용 초안)

> 서버 작업을 각자 자기 계정으로 직접 할 수 있게 게이트(ax-gate)를 엽니다.
> - 팀원마다 서버에 개인 계정을 만듭니다. 책임자에게 SSH 공개키(.pub)와 PC 주소를 보내 주세요.
> - 누구나: 상태 점검, 자동 배포가 막혔을 때 수동 배포(배포 기준 브랜치에 머지된 커밋)
> - 권한자: nginx 변경(새 쓰기 경로는 두 사람 확인), 재시작, 롤백, 배포 잠금
> - 바꾸는 작업은 실행 전에 이 채널에 한 줄(되돌리는 방법 포함)을 올립니다. 문안은 게이트가 만들어 줍니다.
> - 키 만드는 법과 쓰는 법: 레포 `docs/ops/ssh-gate/ANNOUNCE.md`
> - 개인키는 절대 공유하지 않습니다. 공개키(.pub)만 보냅니다.
