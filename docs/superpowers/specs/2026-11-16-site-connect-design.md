# 사이트 연결 화면 (고객사 연결 창구) — 짧은 설계

2026-11-16, 예진 님과 정함. 이번 범위는 **화면(프론트)만**. 실제 플랫폼 앱 등록·OAuth·변환기·DB 연결은 다음 작업.

## 왜
고객사가 AXcellent에 사이트를 붙일 때 사이트 구조를 바꾸거나 코드를 넣거나 서버를 재시작하지 않게 한다. 연결 창구는 AXcellent가 마련하고 고객사는 고르고·누르고·붙여 넣기만 한다. 요구사항 IF-CUS-008(고객사 몰 API로 바꾸는 연결 부품), IF-CUS-006·007(감시·배포 도구 연결)의 화면 쪽이다.

## 목표 / 하지 않을 것
- 목표: 회사 연결 화면(`frontend/src/demo/CompanyConnect.tsx`) 아래 "회사 판매 서버 연결" 칸을 **"사이트 연결"** 로 바꿔, 두 경우를 고르게 한다.
  1. **쇼핑몰 플랫폼으로 만든 사이트** (카페24·고도몰·아임웹·Shopify·스마트스토어): 플랫폼 고르기 → 몰 주소 → 받을 권한 미리 보기 → "○○에서 허락하기" → 연결됨(상태·마지막 수신·웹훅 자동 등록·권한 다시 보기·연결 끊기).
  2. **직접 만든 사이트** (쇼핑몰 한정 아님, 여행사·예약 사이트 등): 이미 가진 것만 골라 연결.
     - 사이트 데이터 읽기(필수): (가) 이미 있는 API 주소 + 지금 쓰는 인증, (나) 읽기 전용 DB 계정. 연결 뒤 "예약 = 주문" 같은 항목 짝을 제안하고 확인만 누른다. **AXcellent 규격(shop-api)을 그대로 쓰는 사이트**(캣북스)는 지금 있는 주소 연결(`Integrations.tsx`, 실제 API)을 그대로 쓴다.
     - 운영 도구 연결(장애 대응): 배포(GitHub Actions·Jenkins·Argo CD), 감시(Zabbix·Grafana·CloudWatch) 토큰 붙여 넣기 또는 로그인해서 허락.
     - 업무 처리(선택): 쿠폰·환불·판매 중지. 관리자 API가 있으면 켜고, 없으면 "담당자에게 처리 순서를 보내요".
- 하지 않을 것(이번): 실제 플랫폼 OAuth·앱 등록, 변환기, DB 접속, 운영 도구 실제 호출, 업종별 용어 바꾸기. 이런 칸은 데모 저장(이 화면 안 상태)으로 동작하고 "준비 중" 표시(`PreparingChip`)를 붙인다.
- 하면 안 되는 것: 고객사에게 코드 추가·스크립트 심기·서버 재시작을 요구하는 문구나 단계. 키·토큰을 화면에 다시 보여 주기(붙여 넣은 값은 앞 몇 글자만).

## 정한 것
- 위치: 회사 연결 화면의 기존 "회사 판매 서버 연결" 자리. 회사(AXcellent) 연결이 끝난 뒤에만 보이는 조건은 그대로.
- 기존 실제 동작(`companyConnection` API: 확인·저장·모드 전환·해제)은 지우지 않고 "직접 만든 사이트 › 사이트 데이터 읽기 › AXcellent 규격 API" 안으로 옮긴다. 이 경로의 시험(`*.test.tsx`)은 그대로 통과해야 한다.
- 모양은 기존 `components/connect/parts`(SectionHead·StatusChip·Facts·DangerRow·More·Notice)와 `card`·`field`·`btn-*`를 쓴다. 새 의존성 없음.
- 시안: 브레인스토밍 화면 `site-connect.html`(①고르기 ②플랫폼 ③직접 만든 사이트).

## 만드는 사람에게 맡김
컴포넌트 나누기, 데모 상태 저장 방식(기존 `demo/store`·`company.ts` 패턴), 권한 목록 문구 세부.
