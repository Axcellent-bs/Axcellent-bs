# 코드 수정 위험도 등급과 등급별 진행 방식

AI 세션이 이 레포를 고칠 때 쓰는 기준이다. 개발 AI가 고객사 레포에 매기는 위험도(`backend/domains/dev/src/dev_agent/risk.py`)와 이름(낮음·보통·높음)을 맞췄다. 개발 AI는 바뀐 파일 경로만 보고 정하지만, 여기서는 **고친 동작이 틀렸을 때 생기는 피해**로 정한다. 같은 백엔드 파일이라도 테스트만 추가하면 낮음이고, 배포를 두 번 실행할 수 있는 코드면 높음이다.

## 등급 나누기

바뀐 것 중 가장 위험한 것이 PR의 등급이다. 애매하면 한 단계 올린다.

| 등급 | 해당하는 수정 | 틀렸을 때 |
|---|---|---|
| 낮음 | 테스트 추가만, 문서, 화면 문구, 이미 있는 데이터를 화면에 보여 주기만 하는 수정 | 화면이 어색하거나 테스트가 빠짐. 되돌리면 끝 |
| 보통 | 한 도메인·서비스 안의 동작 변경, 화면 동작 변경, 파일 핸들·세션 정리 같은 자원 정리, 검사 규칙을 더 엄하게 하는 수정 | 그 기능 하나가 잘못 동작. 데이터·외부 시스템에는 영향 없음 |
| 높음 | 외부에 실행되는 일(배포·되돌리기·결제·메시지 발송), 동시 실행·잠금, 비밀값 저장소, `shared/` 공용 모듈, `shared/contracts` 계약 추가, 인증·권한, 의존성 추가 | 외부 시스템이 두 번 움직이거나, 비밀값·데이터가 깨지거나, 여러 서비스가 같이 멈춤 |
| 금지 | 안전 규칙 파일(`registry.toml`, `thresholds.toml`, `gate.py`), 자동화 파일(`.claude/`, `.github/`, `CLAUDE.md`), 테스트를 지우거나 약하게 하기 | AI가 고치지 않는다. 필요하면 사람에게 이유와 함께 요청한다 |

## 등급별 진행

| 단계 | 낮음 | 보통 | 높음 |
|---|---|---|---|
| 테스트 | 해당 시험 실행 | 실패하는 테스트를 먼저 쓰고 고친다 | 보통과 같고, 동시 실행·실패·재시도 경우까지 테스트 |
| 로컬 확인 | 고친 도메인 테스트·타입 검사 | 고친 도메인 테스트·타입 검사 | 고친 도메인 + 그 모듈을 쓰는 서비스 테스트 |
| 리뷰 | 스스로 diff 확인 | 다른 AI 리뷰 1번 (구현한 쪽과 분리) | 다른 AI 리뷰 1번 + 사람 확인 |
| 머지 | 자동 머지 예약 | 자동 머지 예약 | `needs-human` 라벨, 자동 머지 안 함, 태윤 님께 리뷰 요청 |
| PR 크기 | 여러 개 묶어도 됨 | 기능 하나씩 | 위험 하나씩 (되돌리기 쉽게) |
| PR 본문 | 등급 한 줄 | 등급·이유·확인한 것 | 등급·이유·틀렸을 때 피해·되돌리는 방법 |

PR 본문 첫 줄에 `위험도: 낮음|보통|높음 — 이유`를 적는다.

## 진행 중 생길 수 있는 위험과 대처

| 위험 | 대처 |
|---|---|
| 다른 세션과 같은 파일을 고쳐 충돌 | 시작 전에 열린 PR과 다른 세션 작업 범위를 확인한다. 겹치면 그 세션에 먼저 알리고 순서를 맞춘다 |
| 데모용 메인 클론이 깨짐 | 메인 클론은 `dev`에 두고, 작업은 `.wt/<이름>` worktree에서만 한다 |
| 로컬에서는 통과, CI에서 실패 | 자동 머지는 CI 초록일 때만 된다. 실패하면 그 PR을 고친다. 테스트를 약하게 해서 통과시키지 않는다 |
| 높음 PR이 사람 확인을 기다리며 쌓임 | 높음 PR은 서로 기대지 않게 나누고, 그동안 낮음·보통을 먼저 진행한다 |
| 고치다가 범위가 커짐 | 원래 고치려던 것만 고친다. 새로 찾은 문제는 따로 적어 두고 등급을 다시 매긴다 |
| 공용 모듈 수정이 다른 서비스를 깨뜨림 | `shared/` 수정은 높음으로 보고, 그 모듈을 쓰는 서비스 테스트까지 돌린다 |
