# AXcellent 홍보 웹페이지 (초안)

AXcellent 홍보 브로셔(PDF) 내용을 한 페이지로 옮긴 정적 웹페이지다. 사내 AXcellent 화면(`frontend/`)과는 따로 두고, 외부에 보여 줄 소개용으로만 쓴다.
상태: **초안, 공개 전.** 공개 위치(호스팅)와 연락 수단이 정해지지 않았고 `noindex`라 검색에 나오지 않는다. 작성: 배병환, 2026-11-18.

## 폴더
| 파일 | 하는 일 |
| --- | --- |
| `content.mjs` | **모든 문구·숫자·링크가 여기 한 곳에 있다.** 고칠 때는 이 파일만 고친다 |
| `build.mjs` | `content.mjs`를 읽어 `index.html`을 만든다 (외부 패키지 없음) |
| `index.html` | 만들어진 결과. 직접 고치지 않는다 |
| `style.css`, `app.js` | 모양과 아주 작은 동작(메뉴, 스크롤 나타나기). JS를 꺼도 읽힌다 |
| `assets/` | 사진·화면 캡처·로고. 시연 영상·화면은 `assets/demo/`에 넣는다 |
| `INTAKE.md` | 준하 님께 받을 자료와 넣는 곳 |

## 보는 법·고치는 법
```bash
cd docs/promo
node build.mjs      # content.mjs → index.html
```
만들어진 `index.html`을 브라우저로 열면 된다(서버 없이 열린다). 글꼴(Pretendard)만 인터넷에서 받는다.

## 지금 일부러 비워 둔 것 (비어 있으면 그 버튼·칸은 화면에 안 나온다)
- `links.brochureUrl` — 브로셔 PDF 받기. PDF 검수가 끝나고 공개하기로 정한 뒤에 채운다
- `links.contactUrl`·`links.contactNote` — 상담 연락 수단(Instagram DM, 이메일 등)이 정해지면 채운다
- `story.media` — 시연 영상·화면. 준하 님 자료가 오면 채운다(`INTAKE.md`)
- 인스타 게시물은 **콘텐츠** 칸(`posts.instagram`)에 고객사별로 보인다. 사례 칸(`cases.items[].posts`)에는 고객사 사이트 화면을 넣는 자리로 비워 둔다(2026-11-18 변경).
- `cases.items[].posts` — **고객사 마케팅 사례** 칸(캣북스, 누비투어, 스터디온에듀). 게시물·반응 자료가 오면 채운다. 규칙: 채워진 사례가 하나라도 있으면 모든 고객사 카드가 보이고(빈 쪽은 "사례 준비 중"), 하나도 없으면 `cases.showEmpty`가 `true`일 때만 빈 카드가 보인다. 외부에 공개할 때 둘 다 비어 있으면 `false`로 두면 순환 그림만 남고 카드는 숨는다. 캣북스가 채워지면 `true`로 돌려도 된다
- `site.noindex` — 공개하기로 정하면 `false`로 바꾼다

## 브로셔 PDF와 다른 점 (확인 필요)
| # | 내용 | 웹페이지에서 | 확인할 사람 |
| --- | --- | --- | --- |

| 2 | PDF 12쪽 "환불·쿠폰·판매자 정산 지급은 금액이 기준을 넘으면" | 나눠 썼다: 환불·쿠폰은 기준을 넘으면, **판매자 정산 지급은 항상** 승인. (정산 지급은 금액과 상관없이 항상 사람 승인이다) PDF도 고쳐야 한다 | 준하·병환 |

| 4 | "서버도 데이터도 회사 것입니다" 설치 문구(13쪽) | PDF 그대로 | 재헌·태윤 |
| 5 | 승인 화면 이미지 | 11/13 캡처를 잘라 확인 번호 줄을 흐리고 마우스 커서를 지웠다. 최신 화면으로 바꾸면 좋다 | 병환 |
| 6 | 14쪽 누비투어 "연결 준비 중" | PDF 그대로 | 예진 |
| 7 | **고객사 마케팅 사례 구역**(PDF에 없음): AI 직원이 고객사의 홍보를 기획·제작하고 반응을 모아 다음 기획에 쓰는 순환. 캣북스와 누비투어 칸을 비워 두었다. "반응 수집" 단계는 연결 준비 중으로 표시했다(Instagram 반응을 읽는 길이 있는지 확인 전) | 새로 넣음 | 준하·재헌 |

## 숫자와 출처 (준하 님 확정 필요)
36초(감지부터 기록까지), 17건(AI끼리 주고받은 요청), 실패 주문 7건, 영향 고객 6명, 피해 249,000원, 보상 12,000원. 모두 **시연 환경(가상 데이터)**이며, 출처는 "시연 이슈 기록(시스템이 자동으로 잰 시각)"이다. 어느 시연 이슈 번호인지 정해지면 `story.statsSource`에 적는다. 같은 숫자는 브로셔·인스타 게시물·이 페이지가 모두 같아야 한다(합의 문서는 63초를 36초로 고칠 것).

## 정할 것
1. **어디에 공개하나**: 이 레포는 공개라 `docs/promo/`를 정적 페이지로 공개(GitHub Pages 같은 방식)하거나 별도 레포로 옮길 수 있다. 어느 쪽인지는 아직 정하지 않았다.
2. **연락 수단**: 상담 버튼이 어디로 이어지나.
3. **방문 세기**: 개인정보를 모으지 않는 방식으로만. (추적 링크 #1265는 주문 쪽 측정이라 이 페이지 방문 수는 따로 정해야 한다)

## 실제 반응 숫자를 넣을 때 (사례 구역)
홍보가 실제로 이루어졌다는 수치를 넣는 계획이다. 실제로 잰 값은 넣을 수 있지만 아래를 지킨다.
1. **실제로 잰 값만.** 못 잰 값은 적지 않는다(0으로 채우지 않는다). 숫자마다 **잰 날짜(`measuredAt`)와 출처(`source`)** 가 없으면 화면에 나오지 않는다(`node build.mjs`가 경고한다).
2. **무엇을 잰 값인지 정직하게.** 시연용 가상 고객사 계정(캣북스·누비투어·스터디온에듀)에서 잰 실제 값이다. 실제 기업의 매출·효과를 뜻하지 않는다. 사례 구역 아래 문장(`cases.note`)을 그에 맞게 바꾼다.
3. **측정 기준을 같게.** 게시 후 같은 기간(예: 7일)으로 잰다. 기간이 다른 숫자를 한 줄에 섞지 않는다.
4. **광고 반응**(유료든 아니든 광고로 잰 노출·클릭·비용)은 마케팅 광고 데이터 입력 설계(#1265·#1291)의 자리에 적고, 숫자의 출처(`report_ref`)를 남긴다. 게시물 반응(도달·좋아요·댓글·저장)은 그 설계에 아직 칸이 없어 넓힐지 정해야 한다.
5. 실제 수치를 넣기 전에 PDF·웹페이지·게시물의 "시연 숫자" 문구와 합의 문서의 금지 표현(시연 숫자를 실제 성과처럼 쓰기)을 새 기준에 맞게 고친다.
