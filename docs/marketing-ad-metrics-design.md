# 마케팅: 광고 데이터 수동 입력(B)과 마케팅 화면 입력·추적 링크(C) 설계

상태: **방향 합의, 구현 전.** 제안: 배병환(고객지원), 2026-11-18. 같은 날 예진(기획)·재현(데이터분석) 의견을 받아 아래에 반영했다(반영한 곳은 "(의견 반영)"으로 표시). 마케팅(재헌)·재무(태윤) 확인은 "정할 것"에 남아 있다.
배경: 유입경로 기록 #647 중 남은 3번(외부 광고 데이터)이 막혀 있고, 이것이 데이터분석 #648의 광고 결합(클릭 대비 주문, 광고비 대비 판매액)을 기다리게 한다.
(4번 게시 알림은 재헌 님 몫, 쇼핑몰 화면 #656은 재현 님 몫이다. 이 문서는 B·C만 다룬다.)

## 지금 있는 것 (코드로 확인)
- `CampaignResultInput`(재무 계약)에 `spend_krw`·`impressions`·`clicks`가 이미 있다. 그러나 마케팅 화면 "결과 저장"
  (`CampaignControl.tsx`)은 광고비·쿠폰·판매액·주문만 받고 **노출·클릭 칸이 없다**. 그리고 이 값은 캠페인이 끝난 뒤 한 번 재무에 기록하는 값이라
  데이터분석이 캠페인별로 읽어 갈 곳이 아니다.
- 데이터분석은 "광고 데이터"를 아직 못 읽는 것으로 표시해 둔다(`data_sources.py`의 `AD_DATA_PENDING = "#647 광고 부분 대기"`).
- 링크 꼬리표는 `build_campaign_link`(마케팅 skill, read)이 만든다. 요청자에 `dashboard-api`가 이미 들어 있다. **dashboard-api 경로와 화면은 아직 없다.**
- 광고 플랫폼 연결은 없다(실제 광고는 나가지 않고 광고비는 사람이 보고서를 보고 적는다).

## 원칙
- 숫자는 **사람이 적은 값을 그대로** 저장한다. **빈칸은 "모름"(`None`), 0은 "0원"이다. 둘을 섞지 않는다.** (의견 반영: 재현)
- **마케팅은 저장·조회만 하고 계산하지 않는다.** 클릭 대비 주문, 광고비 대비 판매액 같은 비율은 데이터분석이 계산한다(마케팅이 클릭률을 내지 않는다). (의견 반영: 재현)
- 계약은 `shared/contracts`에 **추가만**. 나중에 광고 플랫폼을 연결해도 호출 모양이 바뀌지 않게 `source`(수동·보고서 파일 등)로 출처를 구분한다.
- 이 화면에도 데이터를 지어내지 않는다. 입력이 없으면 "아직 입력 없음"을 보인다.
- **숫자가 들어오는 길은 하나다**: 마케팅 광고 숫자 → 데이터분석이 읽어 계산 → `campaign_effect` 결과 → 기획이 근거로 받는다. 기획은 마케팅 광고 숫자를 직접 읽지 않는다. (의견 반영: 예진)

## B. 백엔드: 캠페인별 광고 숫자 저장·조회

### 저장 모양
캠페인(`campaign_id`) × 날짜(KST) × 출처(`source`) × 매체(`medium`)당 한 줄. **날짜별로 확정**했다(기획이 성과를 잴 때 넘기는 기간, 데이터분석 `campaign_effect`의 기간과 맞춘다). (의견 반영: 예진·재현)

| 칸 | 뜻 |
| --- | --- |
| `campaign_id` | 받아 둔 기획안의 캠페인 번호. **마케팅이 `receive_campaign_brief` 응답으로 돌려주는 번호(`cmp_` + `proposal_id`, 예 `cmp_PROP-n`)와 같다.** 기획은 이 값을 제안(`handoff.campaign`)에 저장하고 성과를 잴 때 그대로 넘긴다. 모르는 번호는 거절(`unknown_campaign`) |
| `date` | 한국 날짜 `YYYY-MM-DD`. 오늘보다 뒤는 거절 |
| `source`·`medium` | `links.py`의 허용 목록·조합표를 그대로 쓴다(banner·notice·instagram·google·youtube × onsite·social·cpc). 어긋나면 거절. 주문에 남는 꼬리표(#656: `src_source`·`src_medium`·`src_campaign`)와 같은 키라 채널별로 광고 숫자와 주문을 맞출 수 있다 (의견 반영: 재현) |
| `impressions`·`clicks` | 정수 ≥ 0. **`None` = 모름, 0 = 0**. `clicks ≤ impressions`(둘 다 있을 때) |
| `spend_krw` | 정수 ≥ 0 원. **`None` = 모름, 0 = 0원.** 배너·공지(onsite)처럼 광고비가 실제로 0원인 줄은 0을 명시해 적는다(빈칸이면 데이터분석이 광고비 대비 판매액을 계산하지 못한다) (의견 반영: 재현) |
| `entered_by`·`entered_at`·`updated_at` | 적은 사람(사람 토큰에서만, 요청 본문에서 받지 않는다)·처음 적은 시각·마지막으로 고친 시각 |
| `report_ref` | 광고 보고서 이름·번호 같은 근거(선택, 120자) |

- 같은 (캠페인, 날짜, source, medium)을 다시 적으면 **고쳐 쓴다**. 이전 값은 `revisions`에 남겨(시각·적은 사람) 누가 언제 바꿨는지 볼 수 있다.
- 저장은 SQLite 파일 `MARKETING_AD_METRICS_DB`(`run_all.sh`는 `.data/marketing_ad_metrics.db`). 비우면 메모리라 다시 시작하면 사라진다(브리프·미디어 장부와 같은 방식).

### skill (마케팅, 계약은 `schemas/ad_metrics.py` 새 파일)
- `record_campaign_ad_metrics` — 쓰기. 입력: 위 칸. 출력: `recorded`/`updated`/`rejected`+`reason_code`.
- `get_campaign_ad_metrics` — 읽기. **원본 줄만 준다(비율은 계산하지 않는다).** (의견 반영: 재현)
  - 입력: `campaign_id`, 또는 **기간(`from`·`to`, KST, 양 끝 포함)**. `campaign_effect`가 기간으로 돌기 때문에 둘 다 받는다. (의견 반영: 재현)
  - 줄마다: `date`, `source`, `medium`, `impressions`, `clicks`, `spend_krw`(모르면 `None`), `updated_at`, `report_ref`.
  - 합계(노출·클릭·광고비)는 줄 수가 있으면 함께 줘도 된다. **칸에 빈 줄(`None`)이 섞이면 그 칸의 합계는 `None`으로 두고, 칸별 `missing_dates`를 같이 준다.** 그러면 데이터분석이 "몇 일치가 비어서 계산하지 못했다"를 근거에 적을 수 있다. (의견 반영: 재현)
  - 입력이 하나도 없으면 `status: unknown` + 이유("아직 입력 없음"). 0으로 채우지 않는다.
  - 요청자: **`data`, `finance`, `orchestrator`, `dashboard-api`.** `planning`은 뺐다(위 원칙: 숫자가 들어오는 길을 하나로 두고, 나중에 필요해지면 그때 더한다). (의견 반영: 예진·재현)

### 안전 관문
- 기록을 바꾸는 호출이라 `execute()`를 거치는 것이 규칙이다. 금액이 나가는 일이 아니므로 A 등급(자동 통과, 요청자 제한)으로 안전 장치 `registry.toml`에 한 줄을 더한다
  (`receive_campaign_brief`와 같은 짜임, 테스트 `test_registry_actions.py`에 한 건). 이 한 줄이 이 계획에서 **safety 쪽을 건드리는 유일한 곳**이다.
  데이터분석(재현)은 "돈이 나가지 않는 기록이고 data가 읽는 숫자라 `execute()`를 거치는 게 맞다"고 찬성했다.
- 관문이 없으면 쓰지 않고(fail-closed) 입력이 사라지지 않게 화면에 오류를 보인다.

### 건드리는 파일 (재헌 님 작업과 겹침 최소화)
- 새 파일: `marketing_agent/ad_metrics.py`(저장·검증·합계), `contracts/schemas/ad_metrics.py`, 테스트 `test_ad_metrics.py`.
- 한 줄씩 고치는 곳(등록): 마케팅 `handlers.py`·`agent-card.json`, `services/coupon/agent-card.json`, `agent-template/services.py` — 카드는 세 곳을 맞춘다. 재헌 님 확인을 받는다.

### 데이터분석 연결 (재현 님, PR-1 머지 뒤 재현 님이 한다) (의견 반영: 재현)
- `data_sources.py`의 `AD_DATA_PENDING`("#647 광고 부분 대기")을 `get_campaign_ad_metrics` 호출로 바꾼다. 없으면 지금처럼 그 칸만 `unknown`.
- #648 3번: 채널별 클릭 대비 주문, 광고비 대비 판매액은 **데이터분석이 코드로 계산**한다. 주문 쪽 숫자는 #656(주문 꼬리표)이 들어와야 생기므로 그 뒤에 붙인다.
- 손익 숫자는 재무 기록(`record_campaign_result`), 채널별 효율에는 이 일별 광고 숫자를 쓰고, 근거에 출처를 따로 적는다.
- 데이터분석이 계산한 값은 `campaign_effect` 결과에 실려 기획으로 가고, 기획은 그 값을 근거 한 묶음("출처")으로 받아 보여 준다. 기획은 성과 방향(늘었음·줄었음) 규칙에는 넣지 않는다. (예진)
- 평가 케이스에 "입력 없음 / 일부만 있음 / 0원" 세 가지를 추가한다.

## C. 프론트: 마케팅 화면 입력 칸과 추적 링크 복사

### dashboard-api (새 경로)
- `GET /api/dashboard/marketing/campaigns/{campaign_id}/ad-metrics` → `get_campaign_ad_metrics`.
- `POST /api/dashboard/marketing/campaigns/{campaign_id}/ad-metrics` → `record_campaign_ad_metrics`. 사람 토큰만, `entered_by`는 토큰에서 채운다.
- `POST /api/dashboard/marketing/campaigns/{campaign_id}/link` → `build_campaign_link`(읽기). 어긋난 입력은 이유를 그대로 돌려준다.

### 화면 (`/marketing/campaign` 탭, 새 파일)
- `AdMetricsPanel.tsx`: 받은 캠페인마다 입력 줄(날짜·source·medium·노출·클릭·광고비·보고서 근거), 저장된 줄 목록, 합계.
  - source를 고르면 맞는 medium만 보이게 한다. 조합표는 서버 응답에서 받아 화면에 따로 복사해 두지 않는다.
  - **빈칸은 "모름"으로 저장하고, 0은 "0원"으로 저장한다.** 입력 칸 아래에 "비우면 모름, 0을 쓰면 0원"이라고 적고, 저장된 줄에서도 모름은 "–", 0은 "0원"으로 다르게 보인다. 배너·공지(onsite) 줄의 광고비 칸은 기본값을 0으로 채우되 사람이 바꿀 수 있게 한다(제안). (의견 반영: 재현)
  - **클릭률 같은 비율은 이 화면에서 만들지 않는다**(데이터분석이 계산하는 값과 어긋나지 않게). 합계와 줄만 보인다.
  - 사람 토큰이 없으면 입력은 잠그고 읽기만 보인다(`CampaignControl`과 같은 규칙).
  - 입력이 하나도 없으면 "아직 입력 없음"을 보인다(출처가 없어서가 아니라 사람이 아직 안 적었기 때문).
- `TrackedLinkBox.tsx`: 캠페인·source·medium을 고르고 기본 주소를 넣으면 꼬리표가 붙은 링크를 보이고 **복사** 버튼을 둔다(클립보드가 막히면 선택해서 복사하도록 안내, try/catch).
  기본 주소는 **마케팅 설정값으로 두고 화면에서 바꿀 수 있게** 하며 코드에는 박지 않는다. (의견 반영: 재현)
- 결과 저장 칸(`CampaignControl`)은 저장된 광고비 합계를 **미리 채워 주되 사람이 고칠 수 있게** 한다(이중 입력 방지). 합계에 빈 줄이 섞여 `None`이면 미리 채우지 않고 안내만 한다. 고치면 출처가 사람이 적은 값으로 남는다(지금 규칙과 같다).
- 디자인은 AXcellent 공용 클래스(`card`·`field`·`btn-primary`·`btn-ghost`)만 쓴다. 타입 검사를 우회하지 않는다.

2. **PR-2 dashboard-api**: 경로 3개 + 테스트.

## 테스트
- 검증: 모르는 캠페인·미래 날짜·`clicks > impressions`·음수·어긋난 source/medium 거절.
- **모름과 0 구분**: `spend_krw=None`과 `spend_krw=0`이 저장·조회·합계에서 다르게 다뤄진다(0은 합계에 더해지고, `None`이 섞이면 합계는 `None`+`missing_dates`). 화면에서도 둘이 다르게 보인다. (의견 반영: 재현)
- **조회 방식**: `campaign_id`로도, 기간(`from`·`to`, 양 끝 포함)으로도 같은 줄을 돌려준다. 입력이 없으면 `unknown`+이유(0 아님), 일부만 있으면 그 칸의 합계가 `None`+`missing_dates`. 비율 칸이 응답에 없다.
- **요청자**: `data`·`finance`·`orchestrator`·`dashboard-api`는 읽고 `planning`은 거절된다.
- 고쳐 쓰기: 같은 키 재입력 시 값이 바뀌고 `revisions`가 남음, 멱등(같은 요청 두 번은 한 번과 같음).
- 다시 시작해도 파일 저장이 남는다. 관문 거절·무응답이면 저장하지 않는다.
- 프론트: 타입 검사·빌드, 조합표 연동, 빈칸은 "모름"·0은 "0원", onsite 줄 광고비 기본 0, 사람 토큰 없음 시 잠금, 링크 복사 실패 시 안내.
